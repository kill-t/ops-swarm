# v3 第三轮审查后的确定性最大轮次停止路由

## 1. 目标与边界

第 99 步已经保存第三轮开放假设及其独立审查。本片只从第三轮假设、同轮审查、运行创建时冻结的协调策略和截至第 3 轮的真实任务数重新编译路由，保存绑定第 3 轮审查的 `await_human` 或 `candidate_evaluation` 事实，使三轮调查在固定最大轮次形成明确、可查询、可恢复的停止决定。

达到最大轮次后不得产生 `follow_up`，即使审查仍给出完整补查建议也只能保留建议并进入 `await_human`，原因中必须包含 `round_limit_reached`。本片不创建第 4 轮计划或任务，不进入 LangGraph 人工暂停、候选结论、规划、处置或父运行结算；路由到候选评估不表示根因已经客观证明，也不授予执行资格。

## 2. 确定性规则与结果契约

继续复用 `deterministic-review-routing-v1`，不增加模型调用或另一套路由规则。该规则从业务事实重新计算：

- 支持充分，且没有假设反证、审查反证、证据缺口或竞争解释时，进入 `candidate_evaluation`；
- 支持充分但仍有实质异议时，进入 `await_human`；
- 支持不足且没有完整补查建议时，进入 `await_human`；
- 支持不足且存在完整补查建议时，因为 `remaining_rounds=0`，保存 `round_limit_reached` 并进入 `await_human`，完整建议继续保留；
- 第三轮结果绝不允许 `follow_up`，任务容量充足也不能越过冻结轮次上限。

新增 `ThirdRoundRoutingResult`，在第三轮审查结果上增加独立 `third_round_review_route`。存在第三轮计划与审查时，路由必须绑定同一运行、轮次、开放假设和审查身份，决定轮次必须为 3、剩余轮次必须为 0 且路由不能是 `follow_up`；没有第三轮计划时该字段必须为空。前两轮 `review_route` 与 `follow_up_review_route` 保持不可变。

## 3. 图版本与恢复

图 v14 固定为第三轮审查终态图。新运行发布图 v15，在第三轮审查节点后追加纯确定性路由节点：

```mermaid
flowchart LR
    A[图 v14 已有第三轮审查] --> B[review_third_round_hypothesis]
    B --> C[route_third_round_review]
    C --> D[END]
```

图 v1～v14 保留各自拓扑、状态和恢复语义。图 v15 的 state 与 checkpoint metadata 同时固定 `workflow_version=v3`、`graph_version=dynamic-investigation-graph-v15`，不能用 v15 恢复 v14 checkpoint。

路由节点不访问外部模型、工具或来源。事实提交前中断时，新父租约从不可变来源重新编译；事实提交后 checkpoint 前中断时，新父租约复用并复核原记录。两种恢复都不增加模型、工具或预算调用。

## 4. 持久化、能力门禁与失败路径

复用 `investigation_hypothesis_review_routes`。该表已经按审查和业务轮次唯一，同一运行可以保存三份路由事实，因此不新增表、字段或公开 API。查询继续按业务轮次和稳定身份排序。

持久化入口按目标轮次实施精确图能力门禁：首轮沿用既有路由图集合，第二轮沿用第二轮路由图集合，第三轮只允许图 v15。服务即使绕过图直接调用，也不能让 v14 或更早图保存第三轮路由。

每次保存或读取都从当前不可变审查、开放假设、冻结协调策略、连续完成轮次和真实任务行重新编译决定，并核对审查散列、策略散列、决定内容与写入父尝试。租约失效、跨运行来源、轮次不连续、轮次未完成、策略或审查漂移、同轮重复事实以及 checkpoint 自报结果与业务库不一致时拒绝推进。

## 5. 迁移与降级

迁移 `0057_third_round_routing` 只把运行图约束扩展到 v15。存在图 v15 运行，或存在绑定第 3 轮及以后轮次的路由事实时，拒绝降级到 `0056_third_round_review`；允许降级时恢复图 v1～v14 约束。

旧路由、图 v1～v14 checkpoint 和 v1/v2 工作流不回填、不改写。用户 Compose 业务数据库不在本切片自动升级。

## 6. 验收标准

- 完整三轮路径把第三轮清洁充分审查保存为 `candidate_evaluation`；有异议、建议缺失或最大轮次仍需补查时保存为 `await_human`。
- 第三轮存在补查建议时保留全部建议并记录 `round_limit_reached`，任何第三轮结果都不能是 `follow_up`，且不创建第 4 轮。
- 三份路由按轮次稳定查询并分别绑定本轮假设和审查；父运行继续为 `running`。
- 第二轮提前进入 `await_human` 或 `candidate_evaluation` 时不产生第三轮路由。
- 路由事实提交前和提交后 checkpoint 前均可跨父租约恢复，模型、工具、来源和预算账本不变化。
- 图 v14 直接调用存储第三轮路由被拒绝；图 v15 和第三轮路由事实分别受到降级保护。
- 图 v14 仍只完成第三轮审查；Alembic 唯一 head 为 `0057_third_round_routing`。

## 7. 面试表达

> 多轮 Agent 系统不能只在提示词里说“最多三轮”，必须让停止条件成为确定性业务事实。我复用同一套路由规则，从第三轮假设、审查、冻结策略和真实任务数重建决定；在最大轮次即使模型仍建议补查，也只保留建议并路由到人工，不再创建下一轮。路由先落业务库，checkpoint 只保存恢复位置，因此提交前后两个崩溃窗口都能幂等收敛，历史图也不能绕过版本门禁写入第三轮路由。
