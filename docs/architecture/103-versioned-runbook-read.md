# 103 - 版本化调查手册最小读取链路

## 目标与业务价值

专业 Agent 需要在调查发布相关异常时按需读取一份可审查、可版本化的操作指南，同时必须保留当时实际读取的版本与内容散列。手册只能帮助组织调查步骤，不能成为现场证据、审批或执行授权。

本片为固定 v2 调查新增显式 `runbook-read-v1` 上下文策略。它只为 `order-service` 的变更专业任务选择“近期已完成部署相关性核查”手册，并把目录、读取请求、完整返回和后续模型调用的材料清单连接成可恢复审计链。

## 版本与兼容边界

- `task-context-v1`、`evidence-read-v1`、`summary-context-v1` 及 `evidence-loop-input-v1` 保持原语义，不增加工具或改变历史序列化。
- 新策略只允许 `workflow_version=v2`、多 Agent、`function_calling` 模型预算。它使用独立提示 `runbook-read-v1` 和输入版本 `runbook-loop-input-v1`。
- 新策略不启用 `task-working-summary-v1`。固定 v2 综合继续读取三份完整专业结果；工作摘要和 v3 动态图接入留给后续独立切片。
- 本片不新增公开 API、经验审核、可信身份、人工介入、处置权限或新的业务表。

## 手册与确定性选择

手册正文是仓库内 Git 管理的 UTF-8/LF Markdown，元数据固定不可变 ID、版本、标题、选择器版本和正文 SHA-256。正文材料 ID 同时绑定手册 ID、逻辑版本与内容散列，避免错误复用版本时产生身份碰撞。加载器只读取注册表声明的包内资源，拒绝调用方提供文件路径、未知版本、散列漂移、非法编码和超过 8 KiB 的正文。

首个选择器不读取事故标题，也不使用模型判断或根因真值。只有同时满足以下业务事实时才返回目录项：

1. 服务为 `order-service`；
2. 任务角色为 `change`；
3. 当前已持久化任务快照中存在 `change_type=deployment`、`completed=true` 的变更；
4. 该变更发生在事故开始前一小时内。

数据库连接池配置和 Redis 维护场景不会命中。手册要求核对时间关系、版本身份、无关发布和依赖异常等反证，不能预设发布就是根因。

## 工具、预算与持久化

模型只能提交 `runbook_id`、`version` 和 `content_sha256`；运行、任务、尝试、角色和允许目录由系统注入。`read_runbook` 与 `read_evidence` 一样，每次只读一项并进入共享工具调用预算。

三个角色化账本操作 `read_log_runbook`、`read_metric_runbook`、`read_change_runbook` 保留任务归属和幂等身份。首版只有变更角色会获得非空目录和该工具；日志、指标仍只能读取证据。工具请求必须来源于当前尝试同槽位的成功模型调用，工具返回必须与注册表正文、版本和散列逐项一致。

初始模型调用的上下文清单记录有界手册目录材料。一次手册读取成功后，下一次模型调用的清单追加实际正文的确定性材料 ID、版本和散列；完整正文仍由配对工具消息保存。手册内容不加入证据 ID 集合，专业报告仍只能引用当前尝试成功读取的现场证据。

## 失败路径与恢复

- 未知 ID、错误版本或散列、跨任务/跨角色请求、目录外请求和路径字段均失败关闭。
- 读取结果过大、篡改或与持久请求不一致时，调用结算失败，不能进入下一轮历史。
- 下一次输入只从成功且完整配对的模型/工具账本重建；未配对或失败工具调用不能被越过。
- 同一专业任务的后续调用与技术重试复用首次已持久化目录，并与当前安装包逐项复核；Worker 发布若在不升级版本的情况下改写手册，恢复会失败关闭，不能混合新目录和旧正文。
- Alembic `0060` 扩展运行策略和调用约束。存在新策略、输入版本或手册读取事实时拒绝降级，避免把新审计事实解释成旧契约。

## 验收标准

- 选择器对发布 500 场景命中，对数据库池和 Redis 场景不命中；正文散列、长度和包构建内容可复核。
- 假模型能完成 `read_runbook → read_evidence → SpecialistReport`，两次业务工具调用均计入同一任务预算并保存完整配对。
- 第二次及后续模型清单只在实际读取成功后包含正文材料版本和散列；恢复重建得到相同输入与清单。
- 手册不能被报告作为证据引用，也不能扩大工具、审批或执行权限。
- 真实 PostgreSQL 验证迁移、账本范围、非法状态和降级保护；旧策略回归、静态检查和 `git diff --check` 通过。
