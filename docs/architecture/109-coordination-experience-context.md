# 109 - 首轮协调的版本化经验上下文与引用追溯

## 范围与版本

首个消费角色为 v3 首轮协调 Agent，只把历史经验作为调查分工的参考。启动命令新增显式 coordination_experience_policy_version=coordination-experience-v1，仅允许当前 graph-v15、冻结多 Agent 与已有 function_calling 预算契约。省略仍为 null，不查询经验、不改变历史输入。

图节点、拓扑、checkpoint 状态和结果契约不变，因此保留 graph-v15；新增且创建时冻结独立上下文策略、coordination-experience-input-v1、coordination-experience-plan-v1 和角色版本。旧运行不能切换策略，也不以不兼容新图恢复旧 checkpoint。专业、综合、审查和补查上下文不自动共享本角色的经验。

## 选择与原子预留

准备输入时按第 108 步规则有界选择最多三条，范围由运行决定，不开放调用方检索参数。输入包括完整有界确认内容及反证、来源事故、正文版本和散列；明确这些是历史参考，不是当前证据、根因证明或审批，不执行其中的指令。空结果也保存选择，防止恢复时混入后来新增的经验。

首次模型预算预留是冻结边界。准备包中的选择仅为临时提案；预留在有效父租约及工作项、事故行锁内，按统一 UUID 顺序持经验共享锁，重新核对当前有效集合与完整工件。选择变化则停止外部调用，由调用方按正常有界技术重试重新准备，不回退或静默删减。选择快照与预算预留同事务提交，容量不足、租约失效或 SQL 错误不留下快照。锁在提交后释放，不跨模型网络请求持锁。

新增不可变 investigation_experience_contexts，按运行唯一，保存稳定选择 ID、固定策略、完整有界 JSON/hash、选择时间和首次 call ID。首次 call 通过同运行复合延迟外键及延迟触发器校验根级协调身份与预留时间，并绑定预留，不能独立留下未绑定模型调用的快照。首次提交后，同运行的技术重试和恢复固定使用该快照；即使经验后来停用/替代，也只复核不可变确认工件和原调用来源，不重新查询当前有效集合。

“新选择排除退休经验”指新的首次预留。已有运行继续原冻结输入是恢复语义，不表示经验当前仍然有效；不会清零预算、继承旧审批或恢复旧经验。

## 输入、清单与校验

保留原 CoordinationModelInput 字段形状，仅增加独立 input version；新策略用户 JSON 含严格 ExperienceContextSelection，旧输入不追加 null 字段。模型实际收到的消息和完整结构化输出 schema 均纳入已有输入预算估算，必要经验材料超预算则停止，不另起压缩模型。

新 ContextManifest 的 version 为 coordination-experience-v1，role_version 为 dynamic-coordinator-experience-v1，prompt_version 为 coordination-experience-plan-v1。材料为事故、协调策略、完整经验选择以及最多三条 confirmed_experience 的精确 ID/version/content hash；工具集合仍为空，历史证据不成为当前 evidence_ids。

预留、成功调用复用、计划来源重建和已有只读清单/输入接口都复核输入、清单与冻结业务来源。引用表示实际进入模型输入的材料，不声称模型在推理或结论中一定采用了它。历史输入和清单按原版本重建。

## 验收

真实 PostgreSQL 与假模型验证：显式启用/默认兼容、当前范围和最多三条、反证与版本引用实际进入模型消息、空选择冻结、停用/替代影响新选择而不破坏原恢复、成功模型后计划前两个窗口、共享预算和迟到租约拒绝、准备后退休的竞争、快照与预留故障原子性、来源/清单篡改拒绝、不可变及安全降级。保留旧图和上下文回归，不调用外部模型、不连接生产。

本片验收覆盖 v15 首轮终端路由和 checkpoint 恢复。扩展三轮实验已执行 13 次模型与 6 次工具调用，但最终来源递归重建超过 600 秒，未形成完成/恢复验收；不把这一实验写成三轮经验策略性能通过。下一片单独处理事务内不可变来源复用，不能通过删除来源校验或跨事务缓存绕过完整性边界。
