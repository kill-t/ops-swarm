# 110 - 有界来源核验与事务内复用

## 问题与边界

第 109 步的三轮实验完成外部调用后，在来源递归重建超过 600 秒。计划、路由、审查、假设和上下文形成有向无环依赖，多条路径重复验证同一祖先。首轮经验引用增加了每次回查的成本，但不能通过删除来源检查解决。

仅对四类成功的结构化重建结果复用：协调计划、开放假设、独立审查、审查路由。不缓存预算、授权决定、当前有效经验集合、租约入口或模型请求；不修改业务状态、HTTP 契约、图拓扑、输入及 checkpoint 版本，也不增加数据库迁移。

## 单次核验作用域

最外层一次只读来源核验建立作用域，绑定 AsyncSession、根事务、savepoint、当前协程和运行。嵌套验证共享该作用域；最外层退出时丢弃，即使同会话、同事务的下一次业务操作也重新核验。不在模型网络请求、提交、回滚或 savepoint 变化之间复用。

发布请求的完整审批来源重建显式建立同一只读作用域，使顺序访问的四类共同祖先也能复用。作用域退出仍复核依赖，并在返回控制流程前清空；后续业务写入、当前预算、原窗口及凭据核验保持独立。v1/v2 和带待提交 ORM 修改的入口仍沿用原路径。

只保存完整成功结果，以来源函数、运行、ORM 主键及全部加载列的规范指纹为键；返回深副本，拒绝正在访问的来源环，并限制条目数。异常和取消不保存成功。存在未提交 ORM 修改时沿用原核验路径，不使用复用。

## 动态依赖的新鲜度

不可变来源仍依赖可变的任务/轮次状态、调用成功集合、历史租约和事故输入。每次复用前、每个成功结果保存前，通过一条固定 PostgreSQL 查询重新读取同运行依赖集合的表名、主键、xmin 与 ctid。插入、删除、更新和同事务多次 UPDATE 均改变集合或物理行版本；这些内部标记只用于短暂的新鲜度比较，不是业务版本或持久事实。

覆盖运行、事故、工作项、父/专业尝试、轮次、任务、调用、证据、结果、摘要、协调策略/计划、假设、审查、路由及冻结经验链。经验审核依赖的授权审计行也纳入，停用/替代集合不纳入历史冻结材料。查询仅返回有界行标记，不读取大模型输入或日志正文。任一变化使本次核验失败，下一次作用域重新读取，不在变化后继续返回缓存。

数据库戳不能证明 identity map 新鲜。作用域开始时对已加载对象定向刷新，并比较先前加载列；过期对象或未标脏的原地 JSON 变化不能静默获得成功。输入行指纹改变不命中旧结果。当前父租约仍由原事务边界在进入和退出时核对。

## 验收

真实 PostgreSQL 验证作用域隔离、动态集合变化、同事务更新、savepoint、陈旧 ORM、原地 JSON、异常/取消和深副本。完整三轮经验场景及更换父租约后的 checkpoint 恢复同时记录耗时、SQL 次数、模型/工具账本；设置宽裕的耗时和 SQL 上界，不把模拟结果描述为现场证据。
