# v3 人工等待的可信补充、取消与恢复边界

## 目标与最小闭环

在第 111 步不可变终端交接之上，实现 await_human 的状态查询、可信工程师补充和取消。人工材料是主体在提交时作出的陈述、约束或问题，不是已核实现场证据，不修改原开放假设、审查、路由、审批或执行资格。本片不新增页面，不将补充自动注入模型。

本片先完成人工命令闭环，恢复的具体协议与执行后置：graph-v15 已到 END，旧 resume 只能重读旧终端。未来恢复必须创建独立持久任务，固定兼容图/阶段版本并绑定精确人工输入版本，显式预算门禁与审计；不能重新 start/investigate 清零额度或静默把旧 checkpoint 交给新图。等待前原预算、用量和 deadline 全部保留，增加预算须另有可审计决定。

## 状态与命令

原交接保持不可变。等待初始版本 1，每个成功补充或取消生成一条不可变事件，版本连续递增；同父 work_items 行锁串行化命令及任务事件游标。最多 15 次补充，每次最多 5 项、每项最多 1000 字；预留一次取消容量，共最多 16 条事件，防止人工材料无界累积。

补充继续 await_human；取消生成最后一条事件，run 变为 cancelled 并记录完成时间，工作项 completed、handed_off 父尝试和原交接时间不变。Incident 仍 investigating；取消不代表恢复或关闭，不提供同事故重新开始的捷径。await_candidate、旧版本和未交接运行不能使用人工等待命令。

命令必须绑定 handoff_id、source_sha256、expected_wait_version、幂等键和原因；补充携带分类材料。主体由可信 Bearer 注入，工程师须有 manage_incident 权限，客户端不能声明角色/主体/授权。按同运行、同主体、同键识别重放，完整规范命令不同则冲突；已成功旧命令在后续补充或取消后仍可重放其原事件，不重复推进版本。其他主体不取得原主体的重放资格。

## 持久化与可信来源

新增不可变人工等待事件和逐请求业务结果审计。事件绑定精确交接、主体和授权，原始有界 HTTP 命令保留在业务结果中，核对授权原始正文散列与规范命令散列；未知目标和业务冲突也提交拒绝结果。授权准入不等于业务成功；认证、结构/大小等协议拒绝沿用身份/HTTP 层。

查询从真实交接、连续事件、原始命令及授权来源重建，最多读取 17 条事件以拒绝越界。operator_authorizations 不能假定不可变，必须重新核验。取消后的历史交接 GET 与原交接幂等命令仍返回原事实，新人工等待 GET 展示 cancelled。数据库通过复合来源外键、不可变守卫、连续版本/授权校验和延迟双向状态约束保护原子提交。新增迁移替换 0067 状态守卫，旧迁移不修改；有新业务事实时降级拒绝。

## HTTP 与失败语义

- GET /api/v1/investigations/{run_id}/human-wait：当前版本、状态及有界人工事件。
- POST /api/v1/investigations/{run_id}/human-wait/supplements：首次 201、精确重放 200。
- POST /api/v1/investigations/{run_id}/human-wait/cancel：首次 201、精确重放 200。
- GET /api/v1/investigations/{run_id}/human-wait/commands：按持久游标分页查询业务结果，不返回原始正文。

新入口始终要求可信认证，包括 legacy_local 模式。未知运行 404、不是人工等待/过期版本/不同幂等命令/取消后新命令 409、非法正文 422。单命令原始 UTF-8 正文最多 64 KiB。等锁后及提交前重新检查认证期限；业务错误在审计提交后返回。新事实、运行取消状态与 run.human_input_saved/run.cancelled 任务事件原子落库，技术错误整体回滚；迟到 Worker 无有效租约，不能推进取消运行。
