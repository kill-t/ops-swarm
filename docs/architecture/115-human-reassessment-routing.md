# 重评意见的确定性后续路由与持久交接

## 目标与状态

第 114 步的成功重评只保存模型意见。本片在成功提交的同一事务中保存独立、不可变的后续意图，区分 `await_human`、`follow_up` 和 `candidate_evaluation`。原 run 仍为 await_human，原 work/attempt、三轮图和 checkpoint 不变；不创建补查任务、候选方案或执行授权。意图固定 `not_dispatched`，后续消费者必须重新验证当前输入、原预算和权限。

## 确定性规则

精确重建原准备来源、最高终端轮次、完整人工补充前缀、成功模型调用与意见。重用原审查路由规则，按原最高轮与已存在任务数计算容量；不从第一轮重新计数，不创建第四轮。新外层契约保存原规则结果和额外阻断原因，不能通过修改旧路由契约掩盖异议。

人工 `constraint` 是完整保留的未解决约束，模型不能自行解除；存在约束时保守等待人工。原时限到达、次数或累计 Token/费用没有余量、供应商用量超过分配时也等待人工。次数检查对后续补查至少要求专业任务数加综合、审查共 N+2 次，候选意图至少要求一次；这只是最低必要容量，不承诺未来输入或工具可用，实际调用仍必须预留。补查还检查剩余工具次数至少 N 次。未知用量沿用保守分配，不当作零。无约束且支持充分、原假设/重评均无反证、无缺口或竞争解释时才产生候选评估意图；支持不足但有完整建议、原轮次与任务容量足够才产生补查意图。

## 持久化、锁与恢复

迁移 `0071_human_reassessment_routing` 新增 `investigation_human_review_routes`，每重评任务最多一条，稳定 UUID5，绑定 run/job、成功结果及调用、准备来源散列、原路由和等待版本，保存完整决策、预算快照与散列。决策 JSONB 上限为 1 MiB，容纳最多 75 条完整约束与原最多 160 条调用记录，不因重复保存预算而截断必要材料。统一 work→job→Incident 锁序，写入时锁定并复核事故仍在调查。新成功提交原子写意见和路由；有其他阶段在途预留时先保存意见，待预算全部结算后再补齐路由，避免把可变账本伪装成不可变历史。

已有第 114 步成功意见不回写；现有重评 Worker 每次领取前有界扫描最多八条当前成功但缺少路由的任务，使用 SKIP LOCKED 补齐。扫描 SQL 排除非调查事故与在途调用，用实例内游标继续扫描而非反复命中首批；游标不承担业务恢复事实。已知来源拒绝由单候选 savepoint 隔离并记录稳定错误码，不生成有效路由或终止其他重评；数据库及未预期程序异常仍显式失败。补齐不请求模型、不消耗额度；已过期可保存等待人工的停止意图，不延长时限。已补充/取消或 Incident 不再调查的历史任务不新增路由。并发补齐通过原 work 锁和唯一键幂等。补充/取消后既有路由保留，查询单独标记 stale。数据库拒绝改写/删除、跨任务来源、非当前输入及自动意图越过截止时间；有事实拒绝降级。

## 接口与验收

`GET /api/v1/investigations/{run_id}/human-wait/preparations/{preparation_id}/reassessments/{job_id}/route` 始终要求可信 Bearer 和 read，返回 `record`（未形成时 null）、`availability`（pending/current/stale）、`unavailable_reason`（缺记录、来源过时或在途预算）、`current_blocking_reason_codes`（当前约束/预算诊断）。GET 不写入。读取重建成功来源、确定性规则、完整预算前缀与散列；历史不可变事实和当前适用性分开。即使 current 也不代表执行资格。

验收纯规则矩阵、真实 PostgreSQL 来源/不可变约束、成功原子性、重复/竞争补齐、旧意见恢复、补充/取消、时限边界、三轮上限及可信只读接口；假模型完成全链，不依赖外部模型或生产环境。
