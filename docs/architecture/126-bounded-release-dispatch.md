# 本地候选发布的持久窗口与受限派发

## 范围

在068f2e5上落实125要求的远端派发截止和取消隔离。实际代码缺少这些保护，不能仅凭控制面租约推断在途写入已停止。本片交付完整可运行的远端注册、CAS执行、只读查询与取消，控制面可信准入/持久任务/Worker及unknown结算下一片接入。124 prepared与审批false字段保持，不把本地管理端点当业务审批授权。

## 契约

持久演练模式增加/__admin/simulated-release/dispatches：POST注册operation_id、完整command、not_before、expires_at；GET /{operation_id}读取，PUT /{operation_id}执行原命令，DELETE /{operation_id}取消尚未应用的操作。仅order-service、rc1→stable，键精确candidate-release-{规范UUID}，窗口大于0且至多30秒。时间必须带时区ISO8601，归一UTC；服务端采用PostgreSQL clock_timestamp，不由请求者提供执行时刻。

新lab_release_dispatches保存不可变原命令/摘要、固定窗口、创建时间和prepared/applied/cancelled状态及成功命令ID/终止时间。过期是prepared的只读投影，不续期、不自动创建新键；ready仅表示窗口有效，不是业务权限或当前CAS证明。首次注册201、同ID同完整命令和窗口200，异体409；首次执行201，已应用精确重放200只返回历史，取消后或窗口外409不写版本。取消首次/重放200，已应用不能描述为撤销。GET返回完整操作和125回执，历史成功与当前效果仍分离；成功及业务错误响应no-store。

## 原子性与失败

锁序固定发布头→派发记录，查询使用头共享锁。原生触发器对规范候选键强制要求同键持久窗口、原命令及有效prepared状态；旧PUT或直接SQL不能用同一规范候选键越过取消/截止。原命令触发器继续原子推进版本，再自动将派发置applied并绑定成功命令；不能单独伪造applied。派发原文与窗口不可修改，记录不可删除，带数据禁止降级；取消与应用竞争在同一锁序下单胜。

窗口在取得锁之后、插入命令时及延迟提交约束再次按数据库时钟检查，长事务越过截止整体回滚。截止是数据库应用决策与延迟约束的时间边界，不承诺网络响应在截止前到达，也不能承诺提交系统调用的物理时刻。取消等待已获得锁的应用事务完成；若先应用，取消返回冲突，不能撤销已发生的变化。操作和命令必须同事务闭环，保存点可用。

超时或响应丢失后只能查询原操作/125回执，不以不存在自动重发。未来Worker派发截止不得晚于124准备期限、原运行期限和租约；必须重验届时权限、精确审批、预算及CAS。失租/取消后迟到响应不能推进父流程。远端取消未完成或写入尚在途时，不能把本地取消当作远端撤销成功。

本管理入口仅隔离演练后台，不验证业务批准或令牌，不限制其他显式旧管理命令；固定候选命名空间的保护不等于封禁全部演练写入口。未连接生产、真实镜像或CI/CD；版本应用也不代表恢复健康。

## 验收

纯规则验证窗口、严格时间/参数和固定键；真实PostgreSQL/ASGI覆盖实际CAS、注册/执行/取消幂等、竞争、锁等待过期、长事务回滚、原生绕过拒绝、历史损坏、迁移及旧接口回归。仅隔离Testcontainers，未升级用户Compose库。
