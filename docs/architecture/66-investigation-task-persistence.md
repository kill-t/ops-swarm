# 调查轮次、专业任务与尝试持久化

## 1. 本切片目标与边界

第 66 步建立可以独立测试的专业任务事实层，为第 65 篇设计中的固定图接入提供稳定身份、重试记录和只读查询。本切片已验收，具体结果见 [进度记录](../progress/66-investigation-task-persistence.md)。

本切片不接入模型、工具循环或新协作图，不改变现有 v1 Worker 处理流程。内部应用服务在有效调查租约下创建轮次、开始与结算尝试；HTTP 只允许读取。现有运行没有新任务记录时返回空轮次，不根据 checkpoint 伪造任务历史。

## 2. 状态、身份与事务

- 轮次以 `(investigation_run_id, round_number)` 幂等定位，创建时原子保存 1～3 个专业任务及完整分派内容摘要；相同轮次相同内容返回原记录，内容变化拒绝。编号从 1 连续递增，最多三轮，上一轮终态后才能创建下一轮。
- 任务以 `(round_id, task_key)` 标识，角色限定日志、指标和变更；本片服务范围必须等于当前事故服务，跨服务权限留到对应场景切片。目标、时间窗和重试上限创建后不可修改。时间窗必须带时区且不超过一天。
- 任务状态为 `pending → running → succeeded`；失败可在明确允许重试且未到上限时回到 `pending`，否则进入 `failed`。任务保持稳定 ID，状态改变递增 `version`。
- 尝试以 `(task_id, attempt_number)` 唯一标识，终态为 `succeeded`、`failed` 或 `lease_expired`。每个任务最多三次尝试，开始命令携带任务期望版本；同一次开始请求返回原尝试并标记 `created=false`，不能据此再次调用外部能力。
- 尝试关联当前 `investigation_attempts` 和冻结的租约到期时间。接管时在同一事务将旧专业尝试记为 `lease_expired`，再创建新尝试；已耗尽次数时只收敛为任务失败，不新增尝试。
- 所有写入先锁定所属 `work_items`，再检查当前 UTC 时间、租约令牌、运行模式与状态，随后锁定任务；旧 Worker、过期令牌和已结束运行不能结算。时钟在取得锁后读取，避免排队等待消耗租约却仍使用旧时间。
- 结算只保存有限执行摘要或稳定错误码，不保存任意异常文本。相同尝试的相同结算幂等，不同结算拒绝覆盖。摘要表示任务处理记录，不是通过审查的根因或授权。
- 所有任务都进入终态后，同事务把轮次设为 `completed`（全部成功）或 `failed`。技术重试不增加轮次。开始冲突、版本冲突与参数错误不留下半成品记录。

本次任务与尝试状态在业务事务中提交，尝试表保存处理历史。阶段报告、证据材料和 SSE 进度事件在下一片固定图接入时加入同一业务提交边界；当前没有专业取证或阶段事件，不能把本片描述为已实现实时协作。

## 3. 数据与查询

新增 `investigation_rounds`、`agent_tasks`、`agent_task_attempts` 三张表。轮次关联调查运行，任务通过复合外键校验轮次与运行归属，尝试通过复合外键校验任务与运行归属，并关联现有 Worker 尝试。业务状态、终态时间、内容形状、次数与唯一身份由数据库约束兜底。所有外键使用 `RESTRICT`，不提供删除或编辑历史的接口。

`GET /api/v1/investigations/{run_id}/collaboration` 返回轮次、任务与尝试的有界嵌套快照。明细通过一条连接查询读取，按轮次号、任务键与尝试号稳定排序，不跨查询拼接变化中的子记录。最多 3 轮 × 3 任务 × 3 尝试，本片不需要分页。

接口不暴露租约令牌，保留父 Worker 尝试 ID 和租约到期时间。`running` 表示最后提交状态，不承诺租约当前仍有效；过期专业尝试在下一次合法接管时收敛。查询不续租、不结算、不启动 Agent。不存在的调查返回现有 `investigation_run_not_found`，非法 UUID 返回标准 `422`。

## 4. 文件职责与验收

领域契约与状态策略、ORM 表、写入事务、只读投影及 HTTP 路由分别组织在 `investigation/tasks/` 中。应用工厂只装配查询依赖，不把新逻辑堆入既有大路由或调查仓储。

验收覆盖分派校验、生命周期和次数上限的单元测试；真实 PostgreSQL 的重复创建、内容冲突、并发开始、版本冲突、失败重试、租约接管、迟到结算、错误归属与迁移往返；API 的空历史、稳定顺序、错误格式和隐藏令牌。测试不调用模型或遥测服务。
