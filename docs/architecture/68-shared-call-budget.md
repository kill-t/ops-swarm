# 运行级共享调用预算与预留账本

本文记录第 68 步次数/时限预算边界；第 69 步新增显式启用的 [模型输入、Token 与费用预算](69-model-input-budget.md)，未启用的新旧运行继续遵守本文策略。

## 1. 目标与本片范围

第 68 步在冻结 v2 固定图中加入最小 Harness 的调用预算入口：模型次数、工具次数、单个专业任务工具次数、从首次领取起的运行时限。所有专业节点、综合节点和技术重试共用预算，外部操作前先持久化预留。Token、费用和模型窗口预算需要完整模型输入边界，将在后续独立切片实现；现有 Token/费用遥测继续保留，未知用量不能被解释为零。

默认最多 12 次模型调用、18 次工具调用、每任务 6 次工具调用、300 秒运行时限。策略版本为 `call-count-v1`，配置分别限制在 1～60、1～100、1～6、1～1800 秒。时限从父运行首次 `started_at` 计算，包含后续退避与重试等待，不因 Worker 接管重新计时。

## 2. 持久事实与授权边界

- 新 v2 运行创建时原子固定 `call_budget`；启动 API 可以提交范围内的配置，缺省使用默认值。v1 不允许携带该配置。
- 旧运行的该字段为 null，包括第 67 步已有 v2；保持历史未预算路径，查询明确返回 null，不伪造过去调用数为零或追溯授予新额度。新 v2 请求不能通过 null 绕过默认策略。
- 新增 `investigation_call_reservations`。每次记录绑定运行、父尝试，专业调用还绑定专业任务/尝试；操作限定三种固定取证、三种专业分析及一次综合。系统注入身份和操作，模型不能选择预算策略或扩大权限。
- 预留事务先锁父工作项，核对当前租约、运行和事故状态，再校验专业尝试归属。通过账本聚合已预留次数，在同一锁内判断额度并追加记录，防止并发超发。
- 幂等键由父尝试、专业尝试及固定操作产生。同一键只首次返回执行资格，重复键不调用外部操作；专业重试保持任务身份、使用新尝试和新预留，所有旧占用仍计入总额。

## 3. 调用、结算与恢复

预留状态为 `reserved`，操作正常返回后记为 `succeeded`，明确操作异常记为 `failed`，取消、超时或父尝试失联时记为 `unknown`。这些状态描述操作结果，不是供应商 Token 用量或扣费确认。所有预留永久占用次数，不因失败、未知或重试返还；预留后、请求前崩溃可能保守消耗一次额度。

请求发生在短事务之外。专业任务的异步上下文隔离当前任务尝试，综合调用关联父尝试；运行器组织预留、执行和结算，不包含 SQL、提示或 HTTP。新预算路径的真实模型关闭 SDK 自动重试，避免单次预留隐含多次 HTTP 请求。LangGraph 仍负责固定图调度和 checkpoint，没有另写工具循环。

父失败或租约接管在同一父事务把未结算预留记为 unknown，迟到结果不得覆盖它们或推进业务。额度或时限耗尽是不可自动重试的控制结果，Worker 持久失败并收尾子任务；没有预算追加或重置接口。调用期间按剩余运行时限取消等待，已发生费用仍由既有遥测如实记录，不宣称物理请求恰好执行一次。

## 4. 查询与验收

运行查询返回可选 `call_budget`。新增 `GET /api/v1/investigations/{run_id}/call-budget`，返回策略、首次开始时间、截止时间、已预留模型/工具次数以及有界调用历史；旧未预算运行返回 null 策略和 null 计数，历史为空。不暴露租约令牌。预算摘要中的数字是预留数，不是供应商实际请求数或最终图的 `tool_call_count`。

验证纯额度规则、并发争抢最后一次额度、重复预留、跨任务/事故身份、重试不清零、预留后崩溃、父收尾与迟到结算、时限耗尽、专业与综合均受控、复用结果不重复预留、API 配置及历史语义、真实 PostgreSQL 迁移往返。测试使用假模型，不调用真实供应商。
