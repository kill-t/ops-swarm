# 受限异步取证与迟到结果隔离

## 1. 本片范围

第 70 步修复多 Agent 固定图直接执行同步网络查询的问题，先交付异步取证端口和受限线程桥接。复用 Loki、Prometheus、变更和受限 GitHub 适配器的查询、来源及参数校验，不复制 HTTP 或领域规则。Worker 中的现场 v1 与冻结 v1/v2 多 Agent 图接入同一进程级取证执行器；单 Agent 的既有 LangChain 工具线程路径保持兼容，本片不改变其预算机制。

现场 v2 仍禁止启动：固定任务目前依赖冻结快照，下一片须先明确现场观测窗口、快照身份与恢复复用规则。此次线程执行器不承担 Agent 调度、checkpoint 或 MCP。

## 2. 端口与资源边界

- `AsyncInvestigationDataSource` 只定义日志、指标和变更三个异步查询能力；图节点与任务运行器只等待异步结果。
- `ThreadedInvestigationDataSource` 将固定同步适配器桥接到独立只读取证执行器，线程内只执行查询，不调用模型、写业务库或推进图。
- 未注入执行器的图只允许内存冻结数据源；现场来源必须显式装配受限桥接，不隐式回退到同步网络访问。冻结评测无需创建线程池。
- 执行器默认最多 3 个未完成查询，单次调用等待上限 30 秒；构造参数只能收紧至 1～3 个槽位、0～30 秒（不含 0）。这些是 Worker 资源上限，不是模型可改的运行预算，进程间不共享线程槽位。
- 提交前非阻塞申请槽位，容量不足立即失败，不在无界队列等待。已提交查询连同尚未启动的查询占用槽位；只有底层 Future 真正结束或成功取消才释放。
- 每次提交复制当前 ContextVars，以保留各任务身份与 OpenTelemetry 上下文；业务结果只回到原等待协程，不通过完成回调发布。

## 3. 超时、取消与持久化

等待超时抛出明确取证超时；外层取消保持 `CancelledError`。两者都尝试取消尚未开始的查询；运行中的同步请求无法由 Python 线程取消，继续占用槽位直到完成，迟到结果被丢弃、迟到异常被回收。原 HTTP 客户端超时继续生效，不把取消等待描述为远端请求已停止。

v2 调用仍先在原业务事务中预留次数并核对租约，再进入线程桥接；运行时限可以比取证等待上限更早生效。超时或取消保留 unknown 预留，容量拒绝和明确来源错误记录失败，已预留次数不返还。结果正常返回后仍需原租约与任务状态校验；过期租约、父失败或取消后不得生成专业报告或推进业务结果。

本片不新增表、迁移、API 或可恢复业务取消命令。复用既有调用账本、任务结果事务、父收尾和 checkpoint；不能把协程取消测试描述为已经提供人工取消 API。

Worker 关闭时停止接收新查询并取消未启动工作，不阻塞事件循环等待线程退出。运行中的请求依靠客户端结束后释放资源；解释器退出仍可能等待线程。极端卡死来源最多占满固定槽位，需要重启进程处理，不自动扩容或另起线程池绕过限制。

## 4. 验收目标

使用阻塞假传输和事件同步证明三类查询真实重叠且事件循环仍响应；测试超时/取消后槽位不提前释放、容量拒绝不发请求、迟到成功/异常不进入报告、查询来源失败不替换冻结材料、线程上下文隔离及关闭后拒绝。用真实 PostgreSQL 验证预算先于请求、unknown 不返还以及租约丢失时迟到结果不能推进流程；回归冻结 v1/v2、预算图和 checkpoint。
