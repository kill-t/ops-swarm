# 模型调用前的专业取证快照与恢复复用

## 1. 目标与交付边界

第 70 步解决同步查询阻塞，第 71 步解决模型失败后证据丢失：原实现仅在专业报告成功时保存证据，重试会重新查询。先在已有冻结 v2 中交付独立取证快照与复用，再为现场 v2 接入固定观测窗口；本片不开放现场 v2，不把冻结材料改标为现场来源。

新 v2 运行固定 `evidence_policy_version=task-evidence-v1`，历史 v1/v2 保持 null，不给旧 checkpoint 补写推测快照。图节点结构不变，恢复行为根据持久策略选择，不能在恢复旧运行时静默启用新策略。

## 2. 快照身份与时间

每个专业任务最多提交一份不可变取证快照。快照绑定运行、任务、首次采集的专业尝试和成功工具调用；保存角色、服务、任务分派时间窗、冻结快照范围 ID、实际证据和规范 JSON 的 SHA-256。范围 ID 表示使用哪组调查材料，内容散列表示这一次实际读到了什么，两者不能混为一谈。

证据上限 20 条、应用 JSON 上限 128 KiB、数据库 JSONB 上限 256 KiB；拒绝重复 ID、其他角色证据、时间窗外观察和空来源。空结果也是已采集事实，保存空数组，不能用 null 表示。`created_at` 是业务提交时间；工具记录提供请求开始和结束时间，`observed_at` 是证据发生时间，冻结事件可以早于本次采集很久。

快照内容不是模型总结，不增加 LLM 压缩。读取旧快照必须核对任务、范围、时间窗及散列，不按证据 ID 跨事故或跨任务命中。新任务、新范围或处置后新观测不继承旧任务快照。

## 3. 提交与恢复流程

1. 任务进入有效尝试后，检查是否已有该任务的已提交快照。
2. 已存在时核对归属和内容完整性，直接复用，不新增工具预留或外部请求；模型调用仍按新尝试计费并遵守原运行预算。
3. 不存在时按既有预算入口预留并取证，成功工具结算后，在独立业务事务保存快照与 `task.evidence_saved` 事件，再调用模型。
4. 专业结果必须与已保存快照的内容、角色和范围一致；任务成功和父运行最终完成均核对，不能仅凭 checkpoint 返回另一份材料。

工具结算与快照提交是两个明确边界：工具已成功但进程在快照提交前崩溃，表示请求完成但材料未持久化；重试仍需重新取证并增加预算占用。快照提交后模型失败或进程崩溃，重试只重新调用模型。没有“外部请求恰好一次”的承诺。

保存须核对有效父租约、当前专业尝试、运行策略和成功工具记录。相同内容重复提交幂等，不重复追加事件；不同内容拒绝覆盖。父失败、过期租约、旧尝试的迟到写入均拒绝；已提交快照保留用于合法新尝试。未知或失败工具不能产生可复用快照。

## 4. 数据库与 API

迁移增加运行策略字段和 `agent_task_evidence` 表，使用复合外键绑定任务尝试与工具归属，任务 ID 为主键；扩展任务事件类型。存在策略或快照时拒绝破坏性降级。旧记录保持 null，不从历史报告反向伪造工具快照。

启动接口不接受模型指定快照或策略；新 v2 由服务端固定策略，运行查询返回该版本。新增只读 `GET /api/v1/investigations/{run_id}/collaboration/tasks/{task_id}/evidence`，返回快照记录或 null；不存在的运行、任务或跨运行读取返回 404，非法标识返回 422。协作列表不加载完整材料，沿用原错误格式、SSE 游标和本地访问边界。

## 5. 后续现场设计约束

现场各适配器目前按调用当时的时钟取证，变更接口还混合了当前运行清单。因此不能只把冻结范围 ID 替换为 run ID 就开放现场 v2。后续切片需显式固定日志/指标/变更的查询截止时间，区分历史事件窗与当前部署清单采集时间，校验迟到入库和范围内空结果；再将现场快照接入本片的持久化与复用机制。

## 6. 验收

真实 PostgreSQL 覆盖快照提交前后崩溃、模型失败后复用、重复提交与冲突、工具归属和结算状态、跨事故隔离、租约失效和内容篡改拒绝；假模型验证重试工具次数不再增加但模型次数累计。API 覆盖未采集/空结果/已采集和非法读取，迁移覆盖往返与降级拒绝；冻结 v1、旧策略 v2 和 checkpoint 保持兼容。
