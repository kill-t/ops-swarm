# 73 - 现场 v2 持久任务取证

## 目标与状态

本切片已完成实现与自动化验收，范围及结果见 [进度记录](../progress/73-live-task-evidence.md)。将第 72 步的显式窗口接入第 71 步的任务快照与恢复链路，保留固定三专业图，不在本片增加动态协作或 MCP。

## 运行与来源契约

- 开放 `multi_agent + live + v2`。创建事务固定 `observation_cutoff_at` 为服务端创建时间向下取整到 UTC 秒，日志、指标回看 15 分钟，历史变更回看 6 小时。调用方不能指定或更新该字段。
- 新现场运行固定 `evidence_policy_version=task-evidence-live-v1`，定义 Loki、Prometheus 与本地变更 API 的显式窗口组合。证据范围 ID 由运行 ID 和截止时间生成，不同运行不能共用任务材料。
- Worker 为每个运行装配绑定服务与窗口的数据源；现有有界线程执行器执行同步查询，所有调用继续经过任务身份、租约和共享预算入口。
- 首片仅支持 `change_provider=simulator`。配置 GitHub 组合源时，在发起取证与模型请求前显式失败，保留 v1 GitHub 行为，不静默丢弃配置。恢复时也执行同一来源能力检查。
- 历史变更只代表窗口内事件及 `recorded_at <= cutoff` 的记录，不读取当前运行清单，不声明当前部署或回滚资格。运行清单属于后续独立材料；现有执行前校验不改变。

## 持久化与兼容

- 新增迁移 `0035_live_task_evidence`：运行表添加可空截止时间，调整 v2 路由与取证策略约束；现场 v2 必须同时具备固定窗口、策略和调用预算。旧 v1、冻结 v2 均保持空截止时间，不回填。
- 快照与专业结果允许 `live`，保持原冻结字段、默认值与序列化不变，已有内容散列继续有效。现场快照严格核对策略、角色、服务、窗口和受支持来源，不能装入冻结材料。
- 快照沿用业务事务内的材料加事件提交；工具结算与材料提交并非同一事务。提交前崩溃重新查询原窗口并计费；提交后重试复用确切内容，仅重试模型。固定窗口不保证远端历史永不变化，持久快照才保证重放内容。
- 每次快照读取和最终成功结算核对材料策略与运行、任务范围一致；租约失效的迟到结果不得落库或推进图。
- 保留同一 v2 图拓扑及 checkpoint 版本检查。新增现场来源策略与窗口属于运行契约，不用现场图恢复冻结运行；不改变旧冻结任务目标或范围。
- 含现场 v2 运行时拒绝降级，避免删除窗口、改变来源语义。无此类事实时允许恢复上一迁移。

## API 与失败路径

- 开始调查接受现场 v2，默认仍为 v1；运行响应新增只读 `observation_cutoff_at`，已有任务、快照与事件查询展示现场材料。
- 数据源断连、超时、非法响应、来源或窗口不匹配均显式失败；无冻结回退。配置不支持是确定性失败；技术失败按既有有界重试处理，额度不清零。
- 现场成功的 `metrics` 仍为空，不能生成冻结真值评测成绩。查询历史变更不等于具备基于当前部署的处置能力。

## 验收

使用真实 PostgreSQL 和独立 checkpoint 数据库，配合假模型及 HTTP transport，验证创建与 API 约束、窗口在排队和重启后不漂移、三专业异步查询、快照提交前后中断、故障无回退、来源错配及预算复用；回归 v1、冻结 v2 与迁移。自动化验证不能表述为真实模型或 Compose 现场演示。

## 验收中发现的既有问题

冻结场景 `snapshot_id` 包含 `frozenset` 的直接 JSON 序列化，可能因进程哈希种子改变身份；旧冻结恢复用例尚未覆盖独立进程。此片不改旧算法或散列，现场运行身份不受影响。后续先修复确定性身份并明确历史任务兼容，再推进 ContextBuilder，不能直接替换算法后宣称旧 checkpoint 均可继续。
