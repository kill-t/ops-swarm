# 76 - 上下文证据目录与受控详情读取

## 目标与切片边界

为已保存的模型调用提供轻量证据目录和单条详情读取，支持工程师复核当时引用的材料，也为后续模型工具循环建立应用服务边界。目录保留证据完整 summary、来源、时间、角色、所属任务和快照散列，不携带 attributes；详情按引用读取完整原观察，不截断或生成新摘要。

本片只交付应用服务与只读 API，不改变 task-context-v1 的实际模型输入、不启用模型业务工具、不新增工具预算事件、不声称已经节省模型 Token。模型主动选择证据及交互记忆需后续独立切片接入 LangChain 工具循环，届时固定新策略并在调用前预留共享预算；不能沿用旧上下文版本改变历史运行行为。

## 状态与持久化

复用调用账本的 context_manifest、model_input 和任务取证快照，不新建材料副本、数据表或迁移。读取身份以运行 ID 和已保存调用 ID 绑定；专业调用仅能读取该调用清单中的本任务，综合调用能读取清单中的三个任务。目录按角色、任务及证据 ID 确定性排序；已采集空快照显示空条目，历史/工具调用没有上下文清单时返回 null，不能把未采集材料伪造成空查询结果。

清单不是身份认证或业务审批。HTTP 接口沿用本地控制面的现有访问边界，用于事后复核；未来 Agent 工具绑定的运行、调用和角色必须由系统注入，不能让模型通过参数切换其他调用。读取不会改变任务状态、调用清单、预算或审批。

## 契约与校验

目录响应包含运行、调用、上下文策略、以及一到三个证据组；每组保留任务 ID、取证版本、快照 ID、快照散列、数据源模式、服务、窗口和零到二十条条目。单条详情返回同一定位引用及完整 EvidenceObservation。一次目录最多 60 条，详情一次一条，原属性上限 16 KiB；不新增无限查询或任意材料路径。

读取服务先验证调用归属与上下文清单，拒绝重复材料 ID、不符合专业角色的清单；按已有仓储校验快照完整性、来源和范围，并核对清单中的版本、散列及证据 ID。清单引用材料不存在或发生变化，整次读取失败，不返回部分目录或重新取证。详情必须携带目录中的 snapshot_sha256，陈旧引用返回冲突，不能悄悄改读新版本。证据 ID 只在所属快照内解析，不全库搜索。

## API

| 方法及路径（前缀 /api/v1/investigations/{run_id}/calls/{call_id}） | 含义 |
| --- | --- |
| GET /evidence-catalog | 返回目录；无上下文清单的历史/工具调用返回 null |
| GET /evidence/{task_id}/{evidence_id}?snapshot_sha256=... | 读取已被该调用引用的一条完整证据 |

不存在的运行/调用、调用外任务和未知证据返回 404；无上下文清单的详情读取返回 409；快照引用过期、材料缺失或损坏返回 409；非法 UUID、证据 ID 或散列返回 422。错误响应使用既有 error_code/message，不暴露原始异常或数据库内容。接口仅 GET，未增加状态修改命令。

## 验收与后续

用固定材料和真实 PostgreSQL 验证目录与原输入/快照一致、完整摘要和大属性分离、范围隔离、陈旧散列、空快照、材料篡改、只读无副作用，以及旧 API/预算/上下文兼容。假传输现场路径验证来源信息，不作为真实现场演示。

下一片接入有界模型按需读取：模型先看到目录，使用系统绑定的 read_evidence 工具读取详情，保留工具调用配对、预算与上下文材料版本；之后再增加结构化工作摘要。是否需要新表由该切片明确，不提前创建空壳。
