# 77 - 同一尝试内的重复调用身份

## 目标与边界

模型按需读取需要同一专业尝试连续调用同一种操作。原账本按父尝试、专业尝试和操作唯一预留，第二次合法调用会被识别为重放。本片先补齐这项持久化前置条件，后续再接入 LangChain 工具循环、配对交互和新上下文策略；不将账本能力描述为模型已经自主读取证据。

## 身份与接口

预留仓储和 BudgetedCallRunner 新增仅由运行层传入的 `invocation_index`，严格整数，范围 0–99，默认 0。它表示同一父尝试、专业尝试、操作下的调用槽位，不是业务调查轮次，也不是账本全局 `sequence`。不同操作可以使用同一个下标，不要求槽位连续；是否继续调用仍由预算与任务状态决定。下标不是模型参数，不通过 HTTP 开放预留入口。

下标 0 保留原幂等键，非零下标在原键后追加冒号与十进制下标。相同槽位的并发请求只创建一次预留；模型输入或上下文清单不同仍冲突。新的槽位产生新的调用事实，不自动复用查询结果。工具参数与工具消息配对将在工具循环切片单独持久化，本片不扩展工具目录或提供结果缓存。

`GET /api/v1/investigations/{run_id}/call-budget` 的 calls 条目新增 `invocation_index`。无新端点；旧调用显示 0，其他字段与错误语义兼容。

## 数据库与恢复

迁移 `0037_call_invocation_index` 为调用账本增加非空整数列，默认 0，并检查范围及下标与幂等键的一致性。历史记录只补充原调用槽位，不修改原键、模型输入、材料清单、用量或策略版本。存在非零槽位时拒绝降级，以免丢失身份后被旧代码误判。

所有槽位仍在父运行行锁内争抢同一预算。失败、未知和重试记录继续计入运行总次数、任务工具次数、Token 与费用；改变下标不增加预算。技术重试使用新的尝试身份，可以从下标 0 开始，但不能清空已有支出。既有有效租约、状态校验与迟到结算拒绝机制继续生效。

Runner 只执行新创建的预留；同槽位重放明确失败，不自动再次访问外部系统。进程崩溃留下的 reserved 由既有父尝试收尾记为 unknown，不承诺外部调用恰好一次。

## 验收

- 同槽位并发幂等，不同槽位竞争最后一个共享额度。
- 同任务重复工具调用受任务总额限制；同操作多次模型调用共享 Token、输出和费用预算。
- 非零槽位重放不能修改模型输入；Runner 在重放和超限时不调用外部函数。
- 非零预留崩溃后仍记账，新尝试不能重置额度，旧租约不能结算。
- PostgreSQL 迁移保留历史身份，非法下标和键不一致被数据库拒绝，非零历史阻止降级。
- 既有固定图、上下文和查询接口回归通过；旧路径默认继续使用下标 0。
