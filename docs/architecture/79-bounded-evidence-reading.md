# 79 - 专业 Agent 有界按需证据读取

## 目标与开启边界

在已有固定 v2 的专业任务内复用 LangChain `create_agent` 工具循环，让模型先看到本任务证据目录，再使用唯一业务工具 `read_evidence` 读取已持久化快照，最后提交 `SpecialistReport`。综合节点仍使用现有单次结构化调用。取证仍由图执行并先保存快照，本片不增加遥测查询、动态分派、工作摘要或 MCP。

启动请求显式选择 `context_policy_version=evidence-read-v1`，必须同时选择 v2 并提供使用 `function_calling` 的模型预算 profile。省略该字段保持现有行为；已有 v1、无策略 v2 和 `task-context-v1` 不升级。新策略与提示版本随运行固定，旧 `ModelInput` 的序列化与散列保持不变。

## 上下文与工具协议

- 首轮目录从当前有效任务的持久材料直接组装，不伪造已保存的模型调用。目录保留证据摘要、来源、时间窗、版本和快照散列，不包含 attributes；事故和任务身份由系统注入。
- 新模型输入使用独立 `evidence-loop-input-v1` 契约，保存 system、user、assistant 工具请求及 tool 响应。每轮最多一个工具请求，拒绝并行工具批次、重复工具 ID、非法工具和未配对历史；输出工具 `SpecialistReport` 是框架的结构化响应协议，不计为业务工具调用。
- `read_evidence` 仅接受 evidence_id 与 snapshot_sha256。run、task、attempt、角色和父模型调用由运行层绑定；参数不能扩张授权范围。返回完整且有界的单条证据。报告只能引用本次尝试成功读取过的证据；允许无引用报告明确表达证据缺口。
- 每次模型调用的真实输入、输出 schema、工具 schema、材料版本、逐次历史和预算估算可查。预算事务重新加载任务材料并核对已提交交互，不能凭调用槽位或内存历史证明输入一致。

## 预算、持久化与恢复

复用原调用账本、父租约事务和运行额度，不增加调度器。新增三类按角色归属的证据读取操作；它们与最初取证共用每任务工具额度、总工具额度与总时限。每次真实模型请求和业务工具执行之前原子预留；请求后结算时保存有界返回材料。调用身份沿用 invocation_index，新尝试不能重置运行支出。

账本增加工具请求和调用结果 JSONB：工具请求引用同一任务尝试中已成功提交的模型调用及 tool_call_id，并核对参数；结果包含规范化模型消息或配对工具响应及证据内容。结果与结算同事务提交；下一步只能使用成功且完整落库的结果。只读调用交互查询按 run/call 绑定，不返回租约或开放写操作。

非法工具、无效结构化结果、消息不匹配和越权读取终止当前尝试，不通过自动错误修复重试隐式花费预算。成功模型交互进入下一调用前必须持久化；失败记录不作为可继续的消息历史。超时、取消、租约失效和崩溃沿用现有失败/unknown 结算语义；未知模型用量保持未知，迟到写入不能推进任务。

专业节点内部不新增 checkpoint。崩溃后由现有父任务恢复：已提交专业结果复用；未完成专业任务创建新尝试，从同一持久快照目录重新开始，历史调用保留且继续占用共享额度。不重放旧预留，也不承诺供应商恰好调用一次。

## 实现补充与使用限制

框架接口以仓库锁定的 LangChain 1.3.16 / langchain-core 1.6.0 源码及真实 SDK 假传输实验为依据。工具 schema 使用框架实际的 StructuredTool / OutputToolBinding 构造，保存的工具选择值为 ChatOpenAI 最终使用的 required。框架的 structured-response 确认由模型节点生成，不通过业务工具节点。

合法返回也受规范化 JSON 32 KiB 上限约束；超限、非法工具参数、非法结构化输出只保存失败及可取得的供应商用量，不保存未经校验的原始正文。缺失或不完整 token_usage 保持未知；框架解析失败前通过模型回调保留已报告用量。工具失败可能被框架转换成本地错误消息，但后续 prepare 会在预算预留及网络访问之前拒绝不完整历史，不发起自动修复模型调用。

原有任务技术重试策略仍然有效，每次重试建立新尝试并继续占用原运行预算。数据库拒绝迟到的新结果；在父租约仍有效时，已结算且完全一致的命令可以幂等重放，即使专业尝试已经结束。

默认预算没有提高。默认单次输出 4096、累计输出 24000，无法容纳三专业各读取一次再综合所需的七次输出预留；启用者须显式按场景配置，例如单次输出 1024，或合理提高累计输出预算。次数、费用和总时限仍独立生效，不保证每次运行必然读满目录。固定图结果中的历史 tool_call_count 仍表示三次原始取证，新读取及重试次数以 call-budget 查询为准。

## 验收范围

使用真实 LangChain/SDK 与假传输验证目录→读取→报告、完整配对与前置预留、非法/越权/过大响应拒绝、读取参数一致性、输入/输出/次数/时限共享预算、未知用量、两个事故并发隔离、旧路径兼容和崩溃恢复。真实 PostgreSQL 验证事务、约束、幂等冲突、升级与防止审计丢失的降级保护；执行 Ruff、mypy 和差异检查。实际命令与结果见 [第 79 步验收记录](../progress/79-bounded-evidence-reading.md)。
