# 80 - 已完成专业任务的结构化工作摘要

## 目标与范围

从已完成专业任务的持久结果与调用账本生成可查询、不可变的工作摘要，为后续上下文消费建立材料。首版不新增 LLM 调用，不改变模型输入、提示、工具循环或 checkpoint；历史交互裁剪和摘要进入综合上下文作为下一切片。

新创建的 evidence-read-v1 运行固定 working_summary_policy_version=task-working-summary-v1，其他策略和迁移前运行保持 null，不回填摘要。该策略独立于上下文版本，表示结果材料生成规则，不表示模型已经使用摘要。

## 内容与来源

摘要绑定运行、任务、成功尝试及来源最终模型调用，保存任务分配、完整 SpecialistReport、结果与证据快照散列、证据目录、成功尝试实际读取的证据 ID，以及该任务所有已终态调用的 ID、尝试、顺序号、调用槽位、操作、类型、状态和错误码。按需读取的参数按 call_id 引用原 interaction，不复制参数或正文；原始取证调用沿用已有账本状态与任务范围，不新增历史参数快照。目录不包含 attributes，也不把未读取的目录材料称为模型已读。

报告逐字段保留，不用规则猜测自然语言中的反证和未解问题。现有报告只有 summary/findings/evidence_ids/confidence，没有单独的反证、问题或人工约束字段；摘要保留它们在原报告中的表达，但不声称已建立这些独立结构化能力。失败或 unknown 调用是调用事实，不自动解释为证据缺失、查询结果或零用量。原始消息与工具配对仍可通过调用交互接口查询。

## 持久化与失败规则

在现有父租约事务中，任务成功、专业结果、摘要和事件一起提交；摘要校验失败则全部回滚。仅使用已成功保存的最终 SpecialistReport 交互，内容必须与专业结果一致；工具调用必须已终态，成功读取须与当前尝试、快照及模型来源一致。跨任务引用、未终态调用、缺少最终模型报告、来源不一致和超过 128 KiB 均拒绝，不静默裁剪。原有失败与重试额度不变。

一任务一份不可变摘要，版本、内容散列与生成时间保存；重复成功结算复用原记录，改变结果仍冲突。新尝试不会覆盖已完成材料；失效父租约不得写入。数据库绑定任务/尝试归属，限制 JSON 类型与体积，并禁止更新或删除摘要；有摘要或非空摘要策略时降级拒绝，防止丢失审计。旧运行不回填。

## 查询与验收

GET /api/v1/investigations/{run_id}/collaboration/tasks/{task_id}/working-summary 返回版本化记录。合法任务无摘要返回 null；运行或任务不匹配返回 404。不提供写入、覆盖或重新生成 HTTP 接口。查询核对摘要散列及持久来源，摘要不是当前事故事实、长期经验或执行授权。

验收覆盖实际框架完成后的生成、保留完整报告和失败调用、未读目录区分、事务回滚、重复结算、跨事故隔离、来源篡改、租约失效、旧策略不生成、迁移保留与降级保护；使用假模型和真实 PostgreSQL，记录静态检查和可复现命令。
