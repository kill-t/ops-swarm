# 工作摘要进入版本化上下文

## 目标与边界

第 80 步已持久化已完成专业任务的不可变摘要。本片显式增加 `summary-context-v1`：综合节点消费三份摘要，替换原来的独立报告段；完整有界证据仍保留，避免遗漏属性中的反证。摘要保留原报告、来源调用、失败与未知调用引用、目录及实际已读范围。不增加反证或未解问题字段，不从自然语言推断新事实。

专业节点继续使用 `evidence-read-v1` 提示、工具集合和完整配对消息历史；不删除单条工具消息，不引入压缩模型。综合原本不接收专业聊天历史，因此本片不宣称历史压缩或节省 Token。

## 版本与接口

启动接口显式选择新上下文策略，要求 v2、模型预算及 `function_calling` profile；固定 `task-working-summary-v1` 摘要策略。省略字段、旧策略及旧输入序列化保持原行为，不回填旧运行，不改变 checkpoint 图版本。

综合输入包含事故、任务范围、完整证据和 `working_summaries`，不重复提供 `reports`。每条完整摘要记录包含版本、内容散列、任务与尝试身份、来源报告及调用引用。材料清单保留事故、任务分配、证据快照，将三项结果引用替换为摘要引用，共十项；综合提示版本为 `summary-context-v1`，无业务工具。专业清单版本为新上下文策略，专业提示仍为 `evidence-read-v1`。

## 持久化与失败路径

不新增摘要表。迁移仅扩展运行策略约束，要求新策略具有有效摘要策略；已有审计禁止降级。加载和预算预留事务内均从业务表重建并核对摘要、已提交结果、证据及调用来源，缺失、越界或内容不一致时拒绝外部请求。最终实际输入与清单必须与重建值完全一致。

全部必要材料参与输入预算估算，超限直接拒绝，不做隐式裁剪；共享额度与重试计数不重置。摘要仍只来自成功结算任务，重试复用不可变材料，迟到结果仍受既有租约约束。

## 验收

纯单元测试覆盖摘要输入、引用、预算拒绝与旧策略兼容；真实 PostgreSQL 和假 SDK 传输覆盖综合实际收到三份摘要、完整证据、失败引用及隔离，预留事务拒绝篡改，恢复复用摘要。迁移验证旧数据不变、非法策略组合与降级保护；启动 API 验证显式策略和 profile。静态检查、相关回归通过后才能记录为已验收。
