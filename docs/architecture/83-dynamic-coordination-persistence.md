# 动态协调计划持久化

## 目标与边界

本片把第 82 步通过确定性编译的协调提案保存为业务事实，并与实际创建的轮次、专业任务和父 Worker 尝试原子绑定。首次动态计划写入时固定完整 `dynamic-coordination-v1` 策略；后续轮次必须沿用完全相同的策略。当前没有 v3 启动入口、协调模型调用或动态图路由，因此不能表述为动态工作流已经启用，真正的运行创建时冻结留给启动切片。

## 持久化模型

`investigation_coordination_policies` 每个运行最多一行，保存完整策略、版本、SHA-256 与创建时间。`investigation_coordination_plans` 每个轮次最多一行，保存编译计划、策略散列、内容散列、父调查尝试与创建时间；通过复合外键保证轮次、策略、父尝试和运行一致。两张表拒绝更新和删除，存在业务事实时迁移不得降级删除。

查询计划时不只核对计划自身散列，还重建以下来源：固定策略、事故服务与开始时间、目标轮之前的累计任务数、轮次规范与散列、轮次目标和创建时间、任务分派及执行尝试上限、父尝试的运行归属与租约时间窗。任一来源漂移均返回稳定完整性错误。

## 原子性与失败路径

计划服务进入既有 `active_investigation_transaction` 后编译提案，首次写策略，再复用轮次创建核心逻辑写入轮次、任务和事件，最后写计划并重建核对；事务退出前再次校验租约。中途失败或提交前租约失效会整体回滚。

同轮相同内容重放返回原记录；策略变化、计划变化、轮次来源缺失分别稳定拒绝。已有固定轮次的运行不能在中途附加动态策略；已有动态策略时，所有历史轮次都必须具备对应计划来源，防止固定与动态语义混合。

轮次身份函数从原仓储原样提取，继续使用旧 JSON 编码参数。中文目标的历史散列固定回归，避免重构破坏旧 v1/v2 恢复。

## 后续接入

下一片扩展共享调用账本的协调模型操作，在外部请求前预留运行预算，并把结构化返回与计划来源关联。模型接入仍不直接修改旧 v1/v2 图；动态图需要独立工作流版本和 checkpoint 兼容边界。
