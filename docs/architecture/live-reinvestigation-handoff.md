# 现场失败回流与人工交接

沿用现有可信回流准入。只有客观验证明确未恢复、事故仍在调查中且原运行持槽时，工程师才能凭收敛摘要、事故版本和幂等键申请唯一一次回流。协调、分派、专业取证、综合和独立审查沿用原账本、截止和阶段租约。新证据限定在失败验证后的窗口，来源由现有只读端口提供。

graph-v16 成功完成回流审查后，确定性路由持久化 `await_human` 和 `live_reflow_manual_takeover`。保留模型原方向、未解问题、实际观察窗口和预算前缀，供工程师交接。原运行保持 `settled`，事故保持 `investigating`，活动槽位归原运行，防止开启第二条并行处置链。路由事务没有执行租约，也不派生候选任务或新审批；旧批准仍绑定原操作。已阻断或失败的阶段通过原阶段接口展示原因并保留该槽位。

应用编译和 PostgreSQL 原生校验共同约束现场路由。冻结图沿用原契约；已经保存现场人工交接的数据库拒绝降级该策略。代表性验证覆盖实际回滚后业务仍失败、可信准入的重放与唯一性、专业新取证、综合、审查和不可自动派发的交接。测试采用隔离 PostgreSQL、进程内故障服务和固定来源响应。Compose 现场演示纳入发布验收。
