## 有界模型输入策略

状态为已决定，待实现及整栈验收。失败回流保留现有完整冻结来源及材料引用，用于审计、预算核验和 Python/PostgreSQL 精确重建。模型请求按新策略投影，适用于新建的现场动态运行。四阶段基线见[回流整改记录](../progress/reflow-remediation-baseline.md)。

- 在调查运行创建时固定回流输入策略，通过增量迁移将既有运行固定为原策略。新现场运行采用字段投影，其他运行继续用原构建器。协调来源须携带可由数据库重建的版本标记，后续阶段从原冻结来源继承。旧来源保留原序列化和摘要，历史阻断作业保持原终态。
- 协调与专业执行共享一份业务投影。保留事故范围、原假设、反证与未解问题、原证据出处及时间、工作摘要、失败查询、审查意见、人工约束、处置及客观验证结果。历史模型请求只从其业务消息提取当前来源中未独立保存的结构化事实，例如任务范围和工作摘要。按内容或业务身份核对重复材料，保留存在差异的证据版本和来源。跳过历史提示、旧输出与工具协议定义、重复账本明细和授权传输字段。
- 专业执行附当前任务与实际取证窗口、未观测边界和新证据。综合附每个任务的新证据、窗口与专业报告。独立复查再附待审查的精确综合提案。业务来源、任务、证据、报告及前序输入的完整哈希仍由原校验路径绑定。模型只收到当阶段必要的输出契约。
- Python 与 PostgreSQL 使用同一字段规则和现行规范序列化，校验投影包和预算分配一致。结构缺失或无法识别时明确阻断。必要材料超单次限制时保留预算阻断，使用原累计额度、时限、审批及槽位守卫。
