# 正式脚本场景的调用预算基线

本基线描述当前脚本模型的成功路径推导，不代表 Compose 实测统计。冻结历史策略和全局默认值保持原状。

正式入口 `scripts/local_demo/investigation.py` 为新运行显式设置模型 20 次、工具 18 次、单任务工具 6 次、总期限 1800 秒。协调、专业工具循环、综合、独立审查、人工重评、候选评估及失败回流共用同一账本和原期限。

| 场景 | 模型调用成功路径推导 | 工具成功路径推导 |
| --- | --- | --- |
| handoff | 首轮协调1 + 三个专业各2 + 两轮综合/审查4 + 人工重评/候选2 = 13 | 三次取证 + 三次证据详情读取 = 6 |
| recovery | 首轮协调1 + 三个专业各2 + 综合/审查2 + 人工重评/候选2 = 11 | 三次取证 + 三次详情读取 = 6 |
| reflow | recovery的11 + 回流协调/专业/综合/复查4 = 15 | 原6 + 回流新窗口取证1 = 7 |

推导依据为 `scripts/local_demo/fixture.py`：非空专业证据目录先返回 read_evidence，再返回 SpecialistReport；冻结路径先日志/指标后补查变更；现场路径一次分派三个专业。回流只派变更专业。空目录、失败、结构校验拒绝等不能算成功路径。

20次模型上限分别剩余7/9/5次空间，但不是无条件重试保证。每次重试及额外工具循环都消耗原账本；失联用量保持未知，不能减计或清零。1800秒包含等待人工和续接，总期限不会因重试/回流延长。低预算运行可以合法创建并在额度耗尽时安全停止，不强制预算覆盖所有理论最大任务数。

验收时按同一个run_id读取call-budget，按operation统计各阶段预留与结算，分别记录等待交接、候选完成、最终收束的累计值；结果须包括失败/unknown调用，不能只数succeeded。对照上述推导并解释偏差，不为追求数量相等放宽守卫。三场景实际数量、工具循环与重试边界仍由正式演示及对应预算回归验收，尚未有本批整栈结果。
