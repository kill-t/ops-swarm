# 本地脚本演示与可复现验收入口

本入口整理已有隔离演练步骤，不增加业务 Agent 能力或发布前置。使用独立 Compose 项目 `opsswarm-local-demo`、独立命名卷和当前发布装配；已有发布项目及历史数据不迁移、不改写。共享本机端口，因此运行前须确认其他栈未占用。

演示配置由仓库脚本生成，不依赖旧案例、缓存脚本或已有令牌。四类可信角色使用独立随机凭据，原始令牌与环境文件仅保存在忽略的本地演示目录；模型固定为容器网络中的脚本端点，不请求外部模型。工具调用响应引用输入中的证据身份，明确作为工程链演示，不宣传为真实模型推理或实际计费用量。

客户端使用 `credential_id.secret` 访问现有认证接口，环境文件仅保存秘密部分的摘要。读取旧配置时以原凭据 ID 补齐本地秘密。开始调查沿用接口已有的事故版本控制。人工续接从写响应取得任务身份，再读持久状态验证补充、准备、重评和候选的依据。报告保存对象身份和实际轮次，供浏览器及 API 对账。

提供人工交接、正常恢复、未恢复后一次回流三条流程。流程通过现有 HTTP API 提交真实可信命令、等待常驻 Worker，核对执行幂等、业务样本、事故状态、槽位及原预算。只读 GET 可以有界等待；写请求不在网络结果不明时自动重发。每个案例保存独立结构化报告和持久对象身份，失败保持原业务事实。

正常恢复和失败回流在核验条件时读取本地发布头及订单失败响应。观察时间取自订单服务的 HTTP `Date`。由于该时间精确到秒，早于批准时刻的观察允许有限次重新读取。缺少有效服务端时间或仍早于批准时刻时停止核验。控制面继续校验原批准及观察时间窗口。

处置报告记录发布准备的身份、可用性与有效期。准备记录当前有效时才提交执行任务。控制面拒绝请求时，报告保留格式受限的机器错误码，便于与持久命令审计对账。执行和恢复阶段分别记录实际操作 ID、执行尝试和采样尝试，收敛记录附内容摘要以便回读核对。

人工交接场景使用冻结发布故障样本与 v15。首轮只读日志和指标，独立审查提出变更补查，第二轮取得发布依据后持久等待人工。此时重启演示项目的控制 API 和冻结调查 Worker，再比较原等待、任务轮次及调用账本。恢复通过后提交可信补充并完成准备、实际重评与候选评估。恢复和回流场景继续使用现场 v16。

未恢复场景临时停止本演示项目的恢复采样 Worker，在回滚被客观确认后注入连接池故障，再恢复采样。新窗口另登记配置变更。脚本读取命令审计，核对原准入、同键重放和唯一准入拒绝。根据变更记录 ID 查找验证后窗口的现场证据，并核对专业报告、独立复查和人工接管引用同一来源。原预算、已结算账本和回滚修订一并核对。报告保存准入、变更、证据、复查与路由的身份。恢复 Worker 在失败路径也会尝试恢复。脚本通过现有 API 和 Compose 入口操作本地演练。

案例写入前先检查健康、角色与容器 UTC 连续性；存在倒退、明显跳变或依赖不可用时返回环境阻塞报告，不能把缺失观测当作成功，不修补系统时钟或放宽业务窗口。此入口的组件验收与完整 Compose 场景结果分别记录；既有发布欠项不会因脚本存在而自动变为已通过。

## 构建与报告归属

正式发布构建要求受版本控制的工作区干净，将 Git 提交写入运行镜像与前端镜像的 OCI revision 标签。演示预检只读核对所有运行应用容器的实际镜像 ID 和 revision、实际 Alembic head，并保存提交、tracked dirty 状态及 Compose/依赖锁文件 SHA-256。只读取指定标签，不记录容器环境、令牌或配置正文。未跟踪用户文件不参与构建身份。

新报告在 preflight 事件中保存 build-provenance-v1；旧报告不迁移，也不能据此追认为已验证构建。使用 SkipBuild 时依然核对实际容器，工作区有修改、标签缺失或提交不匹配、数据库版本不匹配均返回 blocked_environment，错误报告保留已采集身份。此检查不能替代三场景及保留卷案例验收。
