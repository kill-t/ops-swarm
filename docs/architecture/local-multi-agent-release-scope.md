# 可演示、可恢复的多 Agent 本地事故处置版本

决策日期：2026-11-05。状态：交付范围已决定，新增行为待实现、待验收。本决策收口[64长期路线](64-full-multi-agent-roadmap.md)与[65系统设计](65-agent-system-design.md)的本次交付，不改变既有能力的历史验收状态。

## 1. 产品目标与完成终点

交付一个具有完整工程化业务闭环的多 Agent 个人项目。先完成有展示价值、实际参与业务的核心模块，再接最小协作界面和部署；不按第142步及后续编号自动顺延，不顺带重构历史模块。

本版限定订单服务、本地 Docker Compose、既有专业角色和一种受支持的单步骤演练处置。保留模块化单体、独立 Worker、PostgreSQL、LangGraph、LangChain及既有工具端口，不增加编排框架或通用 Agent 平台。

成功闭环：告警落库 → 动态专业分工 → 受限取证与多轮补查 → 独立审查 → 必要人工补充及实际续接 → 候选与确定性规划 → 可信审批及条件核验 → 受控执行 → 客观恢复验证 → 事故收敛与复盘。

失败闭环：验证明确未恢复 → 在原累计预算及期限内准入一次回流 → 新窗口实际取证、综合和独立复查 → 保存更新结论 → 持久人工接管或明确停止。接管、停止及未支持的后续意图必须有可查询原因、可信操作审计、Worker租约和事故槽位去向；未恢复不能显示为已恢复。不能只保存“待回流”意图，也不要求回流后再次自动执行。

下列必需项、三条代表场景、部署与恢复验收全部通过后，完成演示、发布说明和版本交付即结束。本版之外的想法进入后续版本，不自动追加发布前置；范围变化先形成明确决策。

现场场景的模型默认可用明确标识的脚本模型验证工程链路，不能据此宣称真实模型推理效果。真实模型调用须本会话另获明确授权，不是默认CI条件。固定样本与现场结果分开记录；演练版本CAS不宣传为生产镜像发布或真实生产处置。

## 7. 141与时钟问题独立处理

141完整API欠项包括批准在告警注入前提前拒绝，以及随后131历史授权守卫失败；WSL/Docker时钟倒退另有实测，不能认定全部同根因。先用有限时间探针与首个拒绝边界定位，不继续反复搭建整条历史链。

本版不启用回流新方案再审批执行入口时，141功能欠项保留原状态，不要求按142顺延；若首发主链依赖该能力或受相同缺陷影响，则仍是发布阻断。影响租约、授权及未来时间检查的环境异常必须在选定验收环境消除，不放宽守卫，不自动重启WSL/Docker或修改共享内核参数。

## 8. 验证与发布停止规则

- 权限、预算、状态、事务、幂等、租约和审批绑定的必要测试保留；纯规则优先在下层验证，上层只验契约与代表路径。
- 数据库使用真实PostgreSQL；相同代码状态中已经通过的检查不重复执行，文档变化不重跑业务测试。
- 同根因两次长链失败后停止整链，改用最小探针；只有相关修复或新证据出现后，才复验对应范围。
- 长链默认串行，日志留忽略缓存，禁止放宽业务守卫换通过或自动扩大共享环境操作。
- 发布前只执行选定场景、受影响回归、必要迁移/静态/前端检查，不默认重跑全部历史流程；范围外能力不计为已验收。
- 已实现、部分验收、完整发布验收分别记录。当前全部必需项通过且演示、发布完成后，本版结束，后续想法不得自动成为新的发布前置。
