# 00 - 项目章程与架构设计

日期：2026-08-18

## 目标

从空目录建立 OpsSwarm 的项目边界、协作规范、总体架构、技术栈和数据库逻辑模型，为后续小功能切片提供统一事实来源。本切片只创建文档，不生成业务代码。

## 设计与边界

本阶段先回答“为什么做、系统边界在哪里、关键状态由谁保存、模型能做什么”四个问题。

关键决策如下：

- 控制面使用模块化单体，FastAPI API 与 Worker 分进程运行并共享领域代码。
- 故障演练环境与控制面隔离，第一版不接触真实生产系统。
- PostgreSQL 同时承担业务事实、事件和持久任务，但 LangGraph checkpoint 使用同实例的独立数据库。
- LangChain 用于模型、工具和结构化输出；LangGraph 用于可恢复的显式编排；领域层负责确定性规则。
- API 到客户端使用可重放 SSE，控制命令和审批使用 REST。
- 首个可运行故障选择“新版本触发大量 500”，先验证最短完整链路。
- 完整数据库只做逻辑设计，首切片物理模型限制为 Incident、Alert 和不可变事件三张表。
