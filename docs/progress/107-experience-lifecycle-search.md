# 107 - 有效经验状态、停用与有界确定性检索

## 目标

在第 106 步确认版本之上，让不再适用的经验停止进入新检索，同时保留历史内容和来源追溯。开发基线为 main 的 `52ef401`，用户未跟踪的 `output/` 不属于读取、修改或提交范围。

## 设计与边界

先确定 [有效性与检索契约](../architecture/107-experience-lifecycle-search.md)。历史 confirmed 表示当时经过人工确认，当前 active/disabled 表示现在是否参与检索；正文版本和有效性版本分开。确认事实投影 active/1，唯一不可变停用事实投影 disabled/2，不改写候选、审核或确认正文。本片不支持重新启用、版本替代或模型消费。

停用只允许可信工程师，绑定精确正文版本、内容散列和预期状态版本。完整规范命令包含原因，同主体同键同命令重放原结果，同键异参和终态冲突拒绝；权限与身份过期检查先于幂等。停用与业务成功结果同事务保存，业务校验失败回滚保存点后记录 409/404，数据库故障则整体回滚，授权准入不等于业务成功。

检索范围从持久运行及其事故取得：同服务、固定 local_fault_lab、同 frozen/live；调用方只能选择已有故障标签作为排序偏好。排除同一事故和已停用版本，优先标签命中、确认时间倒序、UUID 升序，SQL 最多选三条，再验证完整冻结工件。来源事故取不可变生成任务快照，不沿用后来变化的报告关联；没有依赖字段时不宣称实现依赖匹配。

停用持 entry 排他锁，检索持共享锁。PostgreSQL READ COMMITTED 下，一个带 NOT EXISTS 的查询可能在等待行锁后仍看到旧子表快照，因此拿到全部选中行锁后，另发新语句复查停用事实。并发剔除后可少于三条，不无界补查；查询只代表本次复核时的有效集合，后续同一 run 查询可变化。

## 实际改动

- `lifecycle_contracts.py`、`lifecycle_policy.py` 定义状态、严格命令、有限响应及纯版本/幂等/终态规则；`lifecycle_validation.py` 校验停用身份、完整命令和可信授权。
- `lifecycle_store.py` 组织行锁、有效状态、保存点及不可变业务结果；复用同事务确认工件加载器，不重新检查可能已经变化的现场来源来阻止停用。
- `search_policy.py` 投影有界摘要，保留人工确认提示、反证标记和来源引用，只去掉展示摘要中的生成时待审尾句；`search_store.py` 负责系统范围、SQL 过滤、排序、上限和锁后复核。
- `lifecycle_api.py` 增加停用、当前状态、按调查范围检索三个可信 Bearer 接口；停用复用仅工程师拥有的 manage_report，读入口要求 read，legacy 拒绝。原确认详情仍返回原始工件。
- 迁移 `0064_experience_lifecycle` 新增两张不可变表、确认版本复合唯一约束及范围表达式索引。停用事实精确绑定正文/来源，业务结果可记录不存在的目标；任何新治理事实阻止降级，空表降级不改写旧确认版本。
- 既有业务链测试夹具增加独立来源键和场景参数，以真实 PostgreSQL 保存多份确认历史；24 个历史集成测试文件仅更新当前迁移 head 字符串，历史降级目标和图恢复语义保持原样。

## 测试方法与结果

最终统一回归 **1,519 项通过**，用时 378.80 秒：单元 1,130 项、API 213 项、整组迁移 176 项。Ruff、格式和 mypy 通过，分别覆盖 621 个 Python 文件和 340 个源文件；唯一迁移 head 为 `0064_experience_lifecycle`。Compose 公开环境配置、文档相对链接、历史测试差异及 Git 差异检查通过，独立最终复核未发现阻塞问题。

```powershell
$migrationTests = @(Get-ChildItem -LiteralPath tests/integration -Filter '*migration*.py' | ForEach-Object { $_.FullName })
.venv/Scripts/python.exe -m pytest tests/unit tests/api @migrationTests -o addopts= -q --disable-warnings
.venv/Scripts/ruff.exe check src tests alembic
.venv/Scripts/ruff.exe format --check src tests alembic
.venv/Scripts/mypy.exe src
.venv/Scripts/python.exe -m alembic heads
docker compose --env-file .env.example config --quiet
git diff --check
```

本片新增纯规则 35 项、API 22 项、迁移 28 项，权限矩阵增加 5 项。API 覆盖排序与上限、服务/来源/同事故隔离、未确认及拒绝排除、停用后排除与旧详情保留、身份/越权/过期/伪造授权、并发幂等与版本冲突、未知目标审计、数据库失败整体回滚和保存点拒绝。

并发测试用独立数据库连接查询 pg_stat_activity，确认真实锁等待再释放事务，分别验证“停用先持锁、检索随后重新复核”和“检索先持共享锁、停用等待快照结束”。另改变当前报告关联，确认来源事故始终来自冻结快照且仍可停用。迁移测试覆盖原生约束、复合引用、不可变触发器、空表回退、有事实拒绝回退及 ORM 一致性。

首次统一回归发现六项迁移检查失败，原因是 PostgreSQL 反射给 JSON 表达式补入括号与 ::text，ORM 文本未规范化；统一迁移和 ORM 表达式后，单项元数据检查通过，再重跑整组回归。没有跳过一致性检查。

数据库均为 Testcontainers PostgreSQL 17.6；固定调查结果和假探针用于业务链，不调用外部模型，不视为现场证据。子智能体承担独立审查、表/迁移/迁移测试和纯规则测试，主 Agent 核实关键结论并统一运行验收。未升级用户 Compose 业务数据库，未重新执行完整发布演示；八项慢速历史动态图降级测试未重跑，其相关文件只更新 head 字符串。

## 限制与下一步

查询返回本次复核时有效的历史参考，尚无模型上下文材料清单、经验工具或图接入，不能声称模型已经使用经验或同一 run 的后续查询固定。历史经验不证明当前根因，不授予执行权限，也不继承旧审批。

第 108 步建立经验版本替代与不可变追溯：可信工程师绑定精确新旧版本，原子保存替代关系和业务结果，保持历史可查并排除被替代版本；随后再做工具与模型上下文引用。本片不预建替代接口或数据库空壳。

## 面试表达

> 我把历史确认内容与当前可用状态分开保存，停用不会抹掉当时的人工决定和来源。停用命令绑定精确版本及散列，用行锁串行化并发请求，事实和业务审计原子提交。经验检索由系统决定事故范围，SQL 确定性排序最多三条；特别处理 PostgreSQL 等待行锁后的旧子查询快照，再发新语句复查停用，防止失效经验进入结果。所有引用仍指向不可变版本，这些材料只辅助调查，不等于当前证据或执行授权。
