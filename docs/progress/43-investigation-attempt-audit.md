# 第 43 步：调查尝试审计与模型成本

## 本步目标

把调查 Worker 每次领取的持续时间、结果、错误和模型用量从临时日志提升为 PostgreSQL 业务事实，为后续作战室展示、成本评测和工作池容量决策建立可信数据基础。

## 设计决策

- 每次任务领取都创建一条独立尝试，重试追加新记录，不覆盖旧历史。
- 领取与创建尝试同事务，成功或失败时任务与尝试同事务结算。
- 租约过期由下一位领取者确定性关闭，不能假设崩溃 Worker 的 Token 或费用为零。
- LangChain 回调只观察请求数与供应商用量，不保存提示词和模型正文；迟到回调不能跨尝试串账。
- 价格随尝试保存快照，费用由仓储层重算；用量不完整或价格缺失时费用明确为空。
- 对外只提供按调查查询的只读接口，不暴露内部租约令牌。

## 实现内容

1. 新增 `investigation_attempts` 表与迁移，保存租约、状态、耗时、错误、模型、价格、Token 和估算费用。
2. 调查仓储在领取、成功、失败和过期路径中原子维护尝试记录，并校验费用重算结果。
3. 常驻 Worker 增加尝试级用量追踪器，通过 LangChain 回调隔离每次处理窗口。
4. 模型配置新增调查价格设置，并兼容复用现有评测价格变量；Compose 工作池透传价格配置。
5. 新增 `GET /api/v1/investigations/{run_id}/attempts` 只读接口，隐藏租约令牌。
6. 更新数据库、API、Worker、技术栈和 README 事实文档。

## 为什么这样设计

`work_items` 只应该表达当前调度状态，如果不断覆盖其中的错误和计数，就无法回答一次调查为何重试、各次尝试耗时多少。独立的尝试事实让队列保持简洁，同时支持可靠性与成本分析。用量和价格可能来自外部供应商，因此系统宁可明确记录“不完整、费用未知”，也不把缺失元数据解释成零成本。

## 限制与下一步

- 后续切片已在 Incident 作战室展示当前调查的尝试历史，详见 [作战室调查尝试与成本展示](../architecture/44-investigation-attempt-workroom.md)。
- 供应商不返回标准 Token 用量时不会启发式估算费用。
- 下一步选择 GitHub、GitLab 或 MCP 的只读变更来源，复用现有 Evidence 安全边界。

## 面试表达

我把任务调度状态和不可变尝试历史分开建模。每次租约领取都会原子创建审计行，任务结算时再原子关闭；费用不信任 Worker 传值，而是使用当次价格快照和 Token 在仓储层重算。这样重试、崩溃接管和模型成本都有一致、可查询的业务语义。
