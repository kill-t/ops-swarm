# 第 48 步：受限 CI/CD 部署事件摄取

## 本步目标

让固定 CI/CD 流水线能够自动追加 `order-service` 的可信部署事实，替代代码引用完全依赖本地管理接口的方式，同时保持模型、GitHub 和部署执行权限不变。

## 设计决策

- 新增独立持久来源 `ci-deployment-ingestion`，不伪装成故障实验室模拟器。
- 使用 `key_id`、Unix 时间戳与原始请求体的 HMAC-SHA256 认证，默认签名窗口 5 分钟。
- 功能默认关闭；只允许固定 `fault-lab`、`order-service`、配置仓库和成功部署。
- 请求必须携带完整 Commit SHA，部署事件默认不能早于接收时间 1 天，也不能来自未来。
- `delivery_id` 作为来源内幂等编号；认证身份、内容或 `deployed_at` 漂移都返回 `409`。
- 持久化认证后的 `source_identity`，调查 Evidence 同时保留 `record_source` 与来源身份。
- LLM 仍只有三个有界只读工具；本步骤不调用模型、不写 GitHub、不执行发布或回滚。

## 实现内容

1. 新增严格部署事件与默认关闭的环境配置模型。
2. 新增最大 16 KiB 的原始请求读取、内容类型校验、HMAC 认证、时效和仓库白名单校验。
3. 新增 `POST /api/v1/deployment-events` 及稳定有限错误响应。
4. 扩展变更记录来源与 `source_identity`，并由 Pydantic 和 PostgreSQL CHECK 双重保护。
5. 增加 Alembic `0025_ci_deployment_ingestion`，为历史记录回填 `local-admin`，存在 CI 审计事实时拒绝有损降级。
6. 保持本地管理入口原有服务端时间语义；CI/CD 精确重放额外校验部署发生时间。
7. 调查适配器以 `(record_source, external_change_id)` 判重，并把真实上游来源写入 Evidence 属性。
8. Compose 只向 `change-service` 注入摄取配置，`.env.example` 补充无真实密钥的配置说明。

## 真实 Compose 冒烟

本轮升级本机业务 PostgreSQL 到最新迁移并重建 `change-service`，使用运行期随机临时密钥完成：

- 新部署投递返回 `201`；
- 完全相同请求重放返回 `200` 和 `deduplicated=true`；
- 相同投递号修改部署发生时间返回 `409`；
- 只读变更工具能取得 CI/CD 记录，并显示 `record_source=ci-deployment-ingestion`、认证来源身份和完整代码引用；
- 重启服务后记录仍存在；
- 验收结束后入口恢复默认关闭并返回 `503`，容器保持健康；
- 订单接口返回 `200`，版本故障关闭，连接池容量为 `50`，Redis 可用。

两次独立现场投递作为追加式审计事实保留在本机 PostgreSQL，没有物理删除。临时 HMAC 密钥只存在于验收进程和短暂启用的容器环境，最终容器已用空配置、关闭状态重新创建。真实模型和 GitHub API 均未调用。

## 为什么这样设计

“请求签名正确”和“业务事实允许写入”是两层不同判断。HMAC 解决固定流水线身份和传输内容完整性，白名单与 Pydantic 解决它能声明什么，PostgreSQL 唯一约束和 CHECK 解决并发、重放及绕过应用时的数据完整性。把已认证身份与事实一起持久化，事故复盘才不需要依赖临时容器日志。

CI/CD 来源与本地模拟来源隔离，既保留旧演练的确定性，又避免自动化部署伪装为人工本地记录。Agent 只消费规范化只读证据，不共享写入口或密钥，因此引入自动化事实来源不会扩大 LLM 权限。

## 限制与下一步

- 当前只有单一 key ID 和共享密钥，没有双密钥轮换窗口。
- 当前只支持一个服务、一个环境和一个仓库。
- 第 49 步已为新 v2 部署事实增加容器镜像 digest；签名证明、运行实例核对和软件物料清单仍未实现。
- 尚未增加真实 GitHub Actions 工作流，避免在没有确定部署平台前创建不可运行模板。
- 第 50 步已通过独立只读运行身份核对最新部署声明；签名运行证明和多实例滚动发布判定仍待实现。

## 面试表达

我为部署事实做了一个默认关闭的窄写入口，而不是通用 webhook。CI 对时间戳和原始 JSON 字节做 HMAC，服务端再限制签名窗口、大小、环境、服务、仓库、状态、完整 SHA 和事件时效。PostgreSQL 持久来源身份并用来源加投递号保证并发幂等，投递号的内容或发生时间漂移都会冲突。Agent 仍只有只读证据工具，拿不到密钥和写接口。这样既能自动建立软件来源，又不会让 LLM 获得部署权限。
