# 59 - 事故复盘报告生成、查看与打印

## 目标

在 Incident 作战室补齐关闭后的最后一个浏览器操作：生成或读取不可变复盘报告，并以适合阅读和打印的只读文档展示。

## 设计与边界

- 只有 `closed` Incident 渲染报告区域。
- 选择事故时自动读取当前报告；报告不存在是可生成状态，不是系统错误。
- 生成请求只包含当前版本和审计操作者，正文始终来自服务端数据库快照。
- 页面核对响应 Incident ID，并用请求代次隔离切换事故后的迟到响应。
- 打印使用浏览器原生能力，不增加 PDF 服务或第三方上传。
- 本步不增加后端接口、数据库迁移、身份认证或复盘行动项。

## 实际改动

- 新增复盘报告 TypeScript 契约和 API 客户端。
- Incident Pinia store 新增报告加载、正常空状态、失败状态、生成状态与消息。
- 新增 `IncidentReportPanel`，展示根因证据、处置审批、执行验证、时间线和 SHA-256。
- Incident 详情页接入报告生成、同步和打印事件。
- 增加响应式屏幕样式与只打印报告本体的 `@media print` 样式。
- 增加 API、store 和组件定向测试以及生产构建验证。

## 限制与下一步

- 复盘报告目前嵌在 Incident 作战室，没有独立报告目录和跨事故筛选。
- PDF 是浏览器生成的派生文件，尚无服务端导出签名或附件存储。
- 报告没有“改进项—负责人—截止日期—完成状态”的闭环。
- 下一步建议建立结构化复盘行动项，并优先做确定性状态与责任跟踪，不让模型直接创建或关闭组织任务。

## 面试表达

> 后端快照完成后，我没有在前端复制报告生成逻辑。页面只提交当前 Incident 版本和操作者，报告不存在作为正常空状态，其他错误失败关闭。store 校验返回记录归属并防止迟到响应覆盖当前选择。报告使用独立可打印版式展示业务快照，浏览器可保存 PDF，但数据库 JSONB 仍是唯一事实来源。
