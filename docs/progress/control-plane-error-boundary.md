# 控制面错误转换与应用装配分离

本批整理控制面应用工厂混合资源装配和 HTTP 错误转换的问题。设计职责补充在 [API 设计](../architecture/05-api-design.md)，保留全部历史错误契约，不删除仍被公开接口使用的错误分支，不改业务判断或持久化。

将错误转换提取到 `control_plane/error_handlers.py`，统一注册和 JSON 序列化，合并人工等待、准备及候选/处置等同形错误处理器。应用工厂从 1,212 行缩至 514 行，继续负责生命周期、依赖、路由和响应元数据。历史错误保留显式字段与状态映射；经验错误继续使用公开 message，401 保留 Bearer 挑战，校验只返回位置、消息及类型，未知异常由框架处理。整理的收益是职责集中和重复封装减少，不能把搬迁代码量描述为全部删除量。

2026-11-08 验证：以整改前实现冻结 198 组响应，对照整改后状态码、正文及原始响应头全部一致；注册集合和完整 OpenAPI 相同。独立语法对照确认工厂签名、生命周期、中间件、依赖及路由装配未变。对照脚本与日志保存在忽略目录 `.pytest_cache/control-errors/`。

可复现回归命令：`uv run pytest tests/unit/control_plane tests/api/test_control_plane_openapi.py`，本轮 35 项通过。新增测试通过真实 ASGI 验证历史错误、带错误码的组件错误、异常子类匹配、认证头、校验输入/上下文不回传、框架异常及实际工厂的响应元数据。Ruff、格式检查、两份变更源文件的 Mypy 和差异检查通过。未启动服务，未跑数据库业务链；本批不涉及事务、迁移或状态规则，不能据此新增整栈验收结论。

完整发布与正式演示三个场景仍保持[上一批待验收状态](local-demo-reproduction.md)，不追加新的重构发布前置。面试表达：先冻结公开错误契约，再按协议转换和资源装配分离职责，删除重复响应代码，用逐项基线与 ASGI 回归证明接口、认证和信息边界保持一致。
