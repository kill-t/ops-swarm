# 当前动态图装配与历史入口分离

当前 Worker 原本通过历史工厂集合加载 v15/v16 实现，现行图还为使用规划协议而导入旧协调图。整改目标是让当前主线拥有清晰的装配入口，保留兼容行为；定义边界见[现场协作设计](../architecture/live-dynamic-investigation.md)。

将当前工厂完整移入已有 `worker/dynamic_factory.py`，旧位置删除实现并重导出同一类，同时移除七项无用导入。首轮规划协议移入协调模块的独立端口文件，旧路径继续导出同一协议。当前图改用端口。原十四个历史工厂、图版本门禁和 checkpoint 实现保持；对比确认原有二十五个顶层类与函数的语法树不变。

新增八项单元验证覆盖独立解释器的导入隔离、旧导入身份、冻结/现场图构造、原运行及租约绑定、共享预算、checkpoint 注入和来源缺失拒绝。入口为 `pytest tests/unit/investigation/test_dynamic_factory.py`。包入口、Worker 主入口/路由/动态处理器及动态图来源/结果契约的定向回归通过。关联检查发现原元数据测试仍以 0097 状态列表核对当前定义，现按 0097 与 0098 的组合契约修正，仅复验失败项通过；迁移与业务约束未修改。Ruff、五个源文件的 Mypy 和差异检查通过。

十五个旧图集成测试文件可正常收集；本轮未执行数据库恢复链、启动服务或调用模型，不改变完整发布尚未验收的事实。详细日志留在忽略缓存。

下一批核对历史工厂实际运行入口、恢复支持承诺和数据契约，再决定退役范围；不以测试引用单独决定永久保留或删除。面试时可说明如何通过公共端口与兼容导出整理历史依赖，同时保持图、预算及恢复行为。
