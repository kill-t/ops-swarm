# 现场人工续接与单步骤恢复

graph-v16 终端交接复用原可信人工和单步骤处置链。迁移接通等待事件、准备、重评、候选与收尾的原生准入；准备清单记录原图版本。人工补充始终作为独立材料，审查和候选评估沿用同一运行账本。没有消费器的补查意图留给工程师接管。见[交付设计](../architecture/live-human-continuation.md)。

## 验证与后续

- `tests/api/test_live_human_continuation_api.py` 在临时 PostgreSQL、脚本模型及进程内演练服务上通过。现场图取用固定变更响应，可信补充经过重评、候选、条件核验和审批；实际 CAS 只派发一次，重放返回原任务。三次订单探针返回 200，发布版本回到 stable，Incident 收敛为 resolved。
- 人工准备定向单元测试、冻结图完整材料及过期租约事务回滚、迁移元数据及空库升降级、Ruff 和受影响模块 mypy 通过。
- 下一片接通一次失败后的现场再调查与明确接管。Compose 现场、保留卷重启及发布演示按发布阶段验收。

## 面试表达

长任务交接后释放调查 Worker。后续 Worker 按原图来源、人工版本和租约领取独立任务，继续原账本。执行端再检查条件与审批绑定，重复请求回读同一持久任务。事故状态由恢复探针和收敛规则推进。
