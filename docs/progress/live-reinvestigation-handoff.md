# 现场一次失败回流与安全交接

graph-v16 复用已持久化的回流准入、协调、分派、专业取证、综合和独立审查。迁移和应用路由共同保存 `await_human` 及现场人工接管原因，保留审查原方向和原预算。事故维持调查状态，槽位归原运行，后续候选 Worker 不会消费该交接。见[现场失败回流设计](../architecture/live-reinvestigation-handoff.md)。

## 验证与后续

- `tests/api/test_live_reflow_handoff_api.py` 通过。真实 PostgreSQL 和进程内演练服务验证回滚成功但三次订单探针均返回 500。同一准入重放返回原事实，第二个幂等键被拒绝。固定变更响应经真实只读适配器采入验证后的新窗口，脚本模型完成专业分析、综合和独立审查。
- 原账本前缀、截止和事故槽位保持。数据库拒绝伪造的候选路由，候选 Worker 未接单，演练接口未新增操作。定向路由单元、迁移元数据及空库升降级、Ruff 和 mypy 均通过。
- 下一项是最小可信协作台。现场 Compose 故障注入、保留卷重启及演示纳入发布验收。

## 面试表达

处置成功与业务恢复分开验证。探针确认未恢复后，可信工程师用原收敛依据申请一次新调查。新证据按验证后的只读窗口采集，独立复查继承同一账本。最后由确定性规则交给工程师，避免沿用旧批准重复处置。
