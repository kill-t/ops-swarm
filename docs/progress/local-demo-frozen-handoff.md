# 冻结补查、重启对账与人工续接演示

`handoff` 从单轮现场等待扩展到冻结样本的完整人工续接。当前 v15 首轮分派日志和指标，独立审查提出变更补查，由原有路由和任务分派实际完成第二轮。第二轮综合引用冻结发布依据，运行进入持久人工等待。报告读取实际任务状态和完成轮次。其余两个场景使用现场 v16。[演示设计](../architecture/local-demo-reproduction.md)

演示启动额外装配冻结 Worker，并使用容器内脚本模型。等待期间只重启演示项目的控制 API 与冻结 Worker。重新鉴权后比较原等待、任务轮次和完整调用账本，差异会阻断续接。通过后提交可信补充、准备、实际重评及候选。候选依据由重评 API 返回的完整路由记录计算摘要，适用于冻结和现场来源。[操作手册](../local-demo.md)

2026-11-09 使用 `uv run pytest tests/unit/test_local_demo.py tests/integration/test_local_demo_handoff.py` 验证，20 项通过。定向回归覆盖只读就绪等待、账本差异拒绝、限定重启目标。隔离 PostgreSQL 和 checkpoint 使用正式脚本、真实 API 及 Worker，重建 API 实例与冻结 Worker 后读回相同状态并完成候选。持久路由依次为 `follow_up` 和 `await_human`，候选沿原预算期限消费后续调用。测试使用固定业务时钟和模型响应。Compose 合并、PowerShell 解析、Ruff 和差异检查通过。实际容器重启及完整发布仍需稳定 Compose 环境复验。

面试时可以展示固定样本如何经过确定性路由触发新任务，以及等待后如何对账原账本并沿相同依据进行重评。区分固定样本、脚本模型与现场取证，区分测试中的进程装配替换与实际容器重启。
