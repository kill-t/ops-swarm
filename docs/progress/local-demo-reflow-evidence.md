# 正式失败回流演示的证据核对

正式脚本此前用 HTTP 409 判定第二次准入被拒绝，并用人工接管路由判断再调查完成。新增失败回流模块，复用原命令和只读 API。按持久审计核对唯一准入、同键复用以及 `reinvestigation_already_exists`，并用新登记的连接池变更 ID 确认实际窗口中的现场材料被专业报告和独立复查引用。复查内容哈希须与接管路由一致，原策略、期限和已结算账本继续可核对，回滚后演练发布头保持一致。[演示设计](../architecture/local-demo-reproduction.md)

报告保留准入、变更、证据、取证窗口与复查身份，演示手册给出重启后读回路径。`python -m pytest tests/unit/test_local_demo.py -o addopts= -q` 通过 31 项。新增定向用例通过脚本实际 HTTP 客户端覆盖成功、其他 409、缺新证据、复查摘要不一致和回流期间发布状态变化。Ruff、格式、文档链接及 Git 差异检查通过。本次使用替代 HTTP 响应验证脚本，正式 Compose 回流与重启读回仍受环境预检阻断。[演示手册](../local-demo.md) [环境预检](local-demo-release-precheck.md)

面试时可以从唯一准入命令讲到变更记录、证据 ID 和接管路由，再展示独立复查的内容哈希怎样把人工接管绑定到这次调查。
