# 正式演示入口与可复现验收整理

本批将依赖忽略目录中旧脚本、手工身份和历史案例的演练流程整理为仓库正式入口，按完整问题完成配置、隔离装配、场景、测试和文档。设计见[复现边界](../architecture/local-demo-reproduction.md)，复制运行命令见[演示手册](../local-demo.md)。未改业务规则、图版本、迁移、预算、租约或审批窗口。

新增 `local-demo.ps1` 与 `scripts/local_demo/`，复用标准发布脚本，以独立项目和卷运行仓库内脚本模型。分别组织人工交接、正常恢复、未恢复后一次回流；通过现有 API、常驻 Worker、真实客观样本和持久记录判定结果，不写数据库或注入运行时实现。写请求结果未知时停止，不盲目重发；失败也保存对象身份和报告。未恢复场景限定控制本项目采样 Worker，并在退出时恢复。配置过期或不完整时拒绝复用。

2026-11-08 实际验证：14 项定向单元用例通过（先运行原有 12 项，HTTP 契约、配置及恢复路径变化后只复验受影响项及新增项）；覆盖独立凭据、真实 Pydantic 契约、证据引用、脚本 HTTP、无自动写重试、环境阻断及采样恢复，包括停止命令结果未知后仍尝试恢复。Ruff 检查和格式检查通过；Windows PowerShell 5.1 实际执行 Prepare、Start、Check、Stop。Compose 配置合并通过，模型消费者均指向内网脚本端点，模型无主机发布端口。

从新隔离卷构建启动成功，迁移、checkpoint 初始化、预配置检查及常驻服务就绪。随后正式预检在 35 秒内发现一次 UTC 倒退和一次超过 100ms 的墙钟/单调时钟差异，生成 `blocked_environment` 报告，尚未开始业务案例。报告位于忽略目录 `.pytest_cache/local-demo/runs/6a80aa43-18f0-4b1b-9060-bb2b7ac81ff6/report.json`。未再次处理 WSL 时钟，已停止本演示全部容器并保留数据；原发布项目仍停止。

本批已验证配置、启动和失败保护入口；三个完整场景脚本仍待稳定环境整栈验收，不能以组件测试或服务健康替代。正常恢复收敛、槽位释放、141 原 API 欠项及完整发布保持原事实。后续使用同一正式入口在稳定环境执行三个代表场景，不恢复旧缓存脚本依赖，也不把共享环境调参作为代码整改前置。

面试表达：将临时验收步骤整理为可从零启动的隔离工程链，脚本模型只产生结构化提案，取证、权限、执行与结果仍由真实业务服务校验；客观观测不满足时明确保存阻断，而不是放宽守卫或宣称整栈成功。
