# 调查与演练包入口按需加载

发布资源诊断发现：读取调查或演练数据模型时，包入口会同时加载单 Agent、LangGraph 调查器或 FastAPI 应用。该依赖来自包级兼容导出，并非数据契约本身需要这些运行器。

调查与演练包的现有公开名称改为按需解析，首次访问后缓存原实现；静态类型检查继续使用显式导入，公开导出和名称发现保持兼容。没有删除 v1/v2、旧图工厂或历史材料，没有改业务守卫、数据库和接口协议。

独立解释器验证纯数据模型导入不加载 LangChain、LangGraph 和 FastAPI。公开导出身份、未知名称拒绝、单 Agent、并行调查、执行与演练相关单元回归通过；Ruff、定向 Mypy 和差异检查通过。测试未调用真实模型。运行镜像构建、标准栈就绪检查及原执行结果的控制 API、网页同源回读通过；恢复初期读探针曾超时，定向回读成功。

完整执行 Worker 的探针仍加载上述框架：历史来源校验沿上下文构建链重建原工具 schema，确实使用 LangChain。当前整理只验收包入口依赖边界，不能宣称完整 Worker 内存已降低或正常恢复链已通过。整栈资源压力及最新失败案例见[资源诊断](local-release-resource-diagnosis.md)。

面试时可说明如何区分契约导入与运行器装配，保留历史导入兼容，并用独立进程测试发现被测试顺序掩盖的导入副作用。下一步在资源充足的选定环境完成原定发布场景，不通过省略历史校验或放宽授权期限解决资源问题。
