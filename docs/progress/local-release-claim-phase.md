# 省去首次派发前的重复阶段读取

本地发布验收中，执行任务被领取时只剩约 5 秒准备窗口，最终在远端写入前因过期被阻断。对隔离库中的同一历史任务做定向探针，完整审批来源重建约 3 至 4 秒，单独读取任务视图只需数十毫秒。原 Worker 在决定走首次派发还是恢复之前先完整读取一次，首次派发事务随即再次读取。

领取返回在父锁下核验的阶段。首次派发直接进入原派发事务，恢复仍以当前租约重建原命令并进行 GET。派发事务、注册后执行授权事务和终端结算各自保留完整校验。任一步超时仍按原窗口和租约处理，审批、幂等及数据库契约继续适用。

执行策略与客户端的 100 项定向单测、首次派发及只读恢复调用探针、Ruff 与差异检查通过。真实 PostgreSQL 首轮通过并发领取、核验变化、预算变化和崩溃恢复，撤权用例在注册前退出。单独复验撤权用例通过，观测到原操作注册后被撤权守卫拒绝 PUT，随后只读查询原操作。隔离发布栈保留命名卷重启，预检拦截过期演练凭据，更新验收配置的有效期后通过。详细测试输出在项目忽略目录。

新事故复验通过调查、可信重评、候选、审批和同键派发。领取时距准备截止约 19 秒，领取到派发标记的时间为 17.6 秒。演练服务返回注册 POST 409、对账 GET 404，未找到对应远端派发记录，控制面记录 `unknown` 和 `release_dispatch_unavailable`。本轮仍未完成首次回滚和恢复采样。下一步按事务测量领取与派发复核，并取得远端拒绝的业务错误码。两次发布复验到达的失败边界不同，均保留原窗口与任务结果。

面试可以用一次任务的时间线解释为什么领取结果足以选择分支，以及为什么真正写入前仍需要新的事务复核。
