# 本地发布入口装配

本地发布使用独立 Compose 项目、镜像标签、命名卷和本机端口。业务迁移与独立 checkpoint 初始化作为一次性服务执行。发布预检要求有效的工程师、审批者、执行者及告警来源凭据，检查工具调用模型预算配置。执行 Worker 继承控制面使用的同一份可信身份绑定。既有独立 Worker 继续消费持久队列。操作方式见[运行手册](../local-release.md)。

隔离 PostgreSQL 新库迁到 `0100_reflow_input_projection`，数据库会话使用 UTC，独立 checkpoint 表已创建。冷启动补齐了订单服务的迁移依赖，延后 Worker 启动到控制面和遥测就绪，并为现场 v3 固定 300 秒处理窗口和 360 秒租约。Docker Desktop 恢复后，最终配置通过启动检查。持续调查 Worker 领取原队列任务，首次取证失败后在同一运行内重试，到达 `await_human`。

使用入口脚本停止再启动，复用了同一命名卷。事故和调查状态可读，完整账本与停止前相同。浏览器通过可信认证、证据读取、人工补充与材料准备，刷新重新认证后可读回补充。第一次提交补充后准备按钮未自动出现，重新打开页面后成功提交，自动刷新行为待定向核查。真实模型请求由本地脚本端点替代。各场景边界见[本地发布范围](../architecture/local-multi-agent-release-scope.md)。

常驻 Worker 接力完成材料准备、独立重评和候选评估，可信审批与同键重复派发通过。本次正常恢复场景在首次处置前被 `release_execution_source_stale` 阻断。领取时准备窗口只剩约 5 秒，实际派发前已到期，处置结果为 `blocked`。下一步定向定位排队和复核耗时，再复验正常恢复及本地发布剩余场景。自动刷新与该时效问题分别处理。

验证使用 `scripts/local-release.ps1` 的启动、停止和状态命令，以及同源 API、Edge 浏览器和只读 PostgreSQL 核对。详细日志在项目忽略目录。Compose 配置、PowerShell 解析、Ruff 和 Git 差异检查通过。

演示时可以对照启动状态说明 API 和独立 Worker 的依赖关系，区分迁移、checkpoint 初始化与实际业务任务消费。
