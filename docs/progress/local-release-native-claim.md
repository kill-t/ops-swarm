# 首次领取复用数据库历史校验

对隔离发布栈的新事故运行分段探针。首次领取耗时约 12.4 秒，其中原请求重建占 10.9 秒。派发事务耗时约 10.1 秒，其中等待父锁 3.2 秒，来源重建 6.8 秒。复核时固定窗口已过期，未发出远端 POST。本次没有复现上次的 HTTP 409，远端具体错误码仍待捕获。

首次领取复用 PostgreSQL 的现有历史守卫，在原锁序下校验冻结请求、授权、审计和初始状态。原生守卫拒绝时继续返回执行任务完整性错误。重领、首次派发、注册后执行授权和只读恢复沿用原复核路径。没有新增迁移。

执行策略及客户端的 100 项定向单测、Ruff 与 Git 差异检查通过。真实 PostgreSQL 并发单领、历史损坏拒绝和崩溃恢复回归全部通过。

发布栈冷启动案例因变更查询失败未进入派发。同容器直连变更服务恢复后热栈复验，首次领取耗时 1.8 秒。派发事务仍因来源重建耗时 22.4 秒而在 POST 前过期，结果为 `blocked`。该轮没有再次触发远端 409，正常回滚与恢复采样仍待验收。详细探针保存在项目忽略目录。

面试时可以用分段计时说明为什么领取只需证明队列事实完整，而派发事务需要重新证明它仍可执行。
