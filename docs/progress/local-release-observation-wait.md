# 隔离发布头观测等待

状态快照后的案例完成材料准备、重评和可信审批，但创建发布准备请求时返回 `candidate_release_observation_timeout`，尚未进入执行。该运行预算结束后保留历史事实，用独立只读探针定位传输边界。

对发布头暂持行锁四秒，原三秒观测稳定返回相同超时，六秒观测约 4.3 秒成功。锁事务回滚，探针前后版本与修订均一致。该对照验证一种可复现的等待来源，原整栈失败的具体持锁方未捕获。

隔离控制 API 配置 `OPSSWARM_EXECUTOR_REQUEST_TIMEOUT_SECONDS=6`，与隔离执行 Worker 的传输等待对齐。固定派发窗口由原业务校验执行。合并 Compose 配置与 Git 差异检查通过，完整正常恢复收敛待新案例复验。

面试时可说明如何分别验证 HTTP 响应等待、操作登记和最终业务效果，并在超时后查询原事实。

恢复采样器的固定订单 GET 同样读取发布头。对相同行锁条件，三秒采样返回 `probe_timeout`，六秒采样约 4.8 秒正确返回故障 HTTP 500，前后修订一致。隔离采样器同步使用六秒 HTTP 等待，依照原三十秒尝试租约、一百二十秒采样窗口及十秒观测有效期验证业务样本。合并配置与差异检查通过，正式恢复仍由任务自身持久化样本确定。
