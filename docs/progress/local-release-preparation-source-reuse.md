# 复用已核验的人工重评准备来源

在仅启动 PostgreSQL 的隔离发布卷上，读取同一个历史执行任务的完整来源。原路径发出 543 条 SQL。准备视图已经核验并重建冻结来源，重评读取随后又重建一遍。现在让准备读取在同一事务内一并返回视图和已核验来源，保留既有准备视图接口。

使用同一镜像、同一历史任务和只读挂载复测，SQL 数量从 543 降到 344，累计 SQL 执行时间从约 1.11 秒降到约 0.72 秒。两次总耗时约 2.18 秒和 2.28 秒，单样本无法证明端到端缩短。探针脚本和输出留在项目忽略目录。

真实 PostgreSQL 的重评精确输入及既有事实保留用例通过，Ruff 与 Git 差异检查通过。发布栈的正常恢复仍需复验。

面试时可区分单次核验结果的事务内复用与跨事务复用。前者消除同一次调用的重复遍历，后续派发与执行前依然独立核验当前状态。
