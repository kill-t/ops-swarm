## 同一冻结案例的输入基线

使用[整栈未恢复案例](local-compose-continuation.md)的回流作业 `d1a4815a-6450-4b36-9a0e-e14accb64310`。从隔离 PostgreSQL 以只读事务读取作业的冻结来源及准入账本，核对来源 SHA-256 后使用四个现有构建器重建输入。统一口径为完整 `ModelInput` 的紧凑 UTF-8 JSON 字节数，估算 Token 为字节数加 256。

| 阶段 | 字节 | 估算输入 Token | 超 48,000 | 证据 |
| --- | ---: | ---: | ---: | --- |
| 回流协调 | 52,117 | 52,373 | 4,373 | 持久冻结来源重建，与现场预算阻断记录一致 |
| 专业执行 | 53,718 | 53,974 | 5,974 | 回放估算 |
| 综合 | 64,420 | 64,676 | 16,676 | 回放估算 |
| 独立复查 | 67,606 | 67,862 | 19,862 | 回放估算 |

协调阻断发生在模型调用前，数据库中没有这次调用尝试。后三阶段复用同一冻结来源和原准入账本，按演练脚本分派一个变更调查任务，使用一条占位新证据和离线结构化报告及提案。综合与复查内嵌分派和原准入账本，现场分派时还会计入真实协调调用，实际字节会随现场结果变化。测量只在离线进程临时放宽分配器的构造上限，无模型或遥测请求，无业务写入。详细输入和复现脚本保存在项目忽略目录 `.pytest_cache/compose-local-smoke/`，使用仓库根目录作为 `PYTHONPATH`，运行该目录的 `replay_reflow_baseline.py`。

## 下一步与面试表达

原调查材料单项占 28,664 字节，候选来源又内含已独立保存的审查及人工输入。后三阶段的估算表明，协调通过后仍可能在后续调用超限。下一切片需要区分用于核验的完整持久来源与模型需要阅读的业务字段，同时在 Python 和 PostgreSQL 固定投影版本并对比重建结果。发布仍需同类故障在原预算和截止下完成新取证、独立复查、持久接管，并确认原账本、事故槽位与唯一处置操作。

面试时可说明如何从持久冻结事实定位调用前阻断，如何用同一来源测量多阶段复制成本，以及为什么把真实守卫结果与下游回放估算分开报告。
