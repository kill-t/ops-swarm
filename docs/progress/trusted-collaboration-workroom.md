# 最小可信协作台

现有事故详情新增可信协作台。操作者用既有凭据验证身份，页面按角色显示操作。只读导航定位 graph-v16 当前工作，展示轮次、证据、独立审查、预算及经验引用。人工补充、核验、审批、回滚与回流沿用既有 API。可信 SSE 断线使用已交付游标续读，原命令失败重试保留幂等键。见[协作台设计](../architecture/trusted-collaboration-workroom.md)。

- 前端构建通过。组件与 HTTP 测试覆盖角色操作、命令版本和摘要绑定、失败重试及 SSE 续读。四项已有组件测试在高并发下超时，降低并发定向复验通过。
- 复用现有 `ops-swarm-control-db-1`。原库迁移停在 `0029_follow_up_governance_idx`，在同一实例的隔离验收库应用仓库迁移。真实 PostgreSQL 与 ASGI 验证无凭据和告警源拒绝、人工重评后候选来源摘要及任务定位。验收库已清理，容器恢复原停止状态。Ruff、mypy 与差异检查通过。
- 下一项是 Compose 部署及发布。使用当前容器和已有业务卷前须确认现有数据的迁移路径，发布验收包含浏览器和现场联调。

面试表达：浏览器只负责呈现可信主体的能力和提交显式命令。授权、审计、版本及幂等在服务端确定，断线后按持久状态重新建立工作视图。
