## 验收与停止线

以下是本轮的工程门槛，在看结果前固定。

| 指标 | 通过条件 |
| --- | --- |
| 完成率 | 两组均完成 15/15，且用量完整 |
| 故障服务 Top-1 | 按需至少正确 14/15，且比全量少正确至多 1 例 |
| 整次调查总 Token | 按需比全量至少少 25% |
| 端到端耗时 | 按需的耗时中位数比全量最多增加 2 秒 |

全部通过即暂停这个方向的优化，保留为离线候选策略，记录实际准确率、用量及耗时。上线前另行验证边界体积、其他服务系统和真实工作流。

有门槛未过时，只在原始数据与错误记录指向一个可复现的具体机制时做一次针对性优化，再用另一批 15 个新案例按同一门槛复验。无法定位可修机制就先关闭本轮。复验无论是否通过都收口，最多追加 30 个案例、一次策略修改。API 凭据或服务不可用时保留部分记录，等待环境恢复后再判定；这类阻断单独记录。

收口后转向单 Agent 与动态多 Agent 的对照。在同一证据和模型下分开统计简单题及需多轮补查的题，优先验证复杂任务完成率、关键证据覆盖和代价。该方向单独设门槛。
